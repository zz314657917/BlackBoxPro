# Task Contract: bbp-sprint-006-germ-real-physical-click

## Task ID

`bbp-sprint-006-germ-real-physical-click`

## Role

Developer Generator. Codex remains the final Evaluator.

## Goal

Enhance the Forge `1.12.2` Germ physical click path so `click_germ_component` can produce real client-side click evidence on a Germ GUI.

This sprint must prove a client event or component click path, screen coordinates, component bounds, and an observable business side effect. It must not use `germ_gui_part_dos execute=true` as the proof path.

## Contract Amendment 2026-05-05

The runtime acceptance target is now a controlled fixed Germ test page, not the Lmshop production-like page. The Lmshop page remains diagnostic background only because it can expose callable obfuscated hooks without producing a stable business side effect.

The fixed page source lives in `docs/workflow/fixtures/germ/blackboxpro-fixed-click.yml` and is copied into the acquired test-cell GermPlugin `gui/` directory only for runtime QA. This transient runtime fixture install is allowed for Sprint 6 retest; it must not be committed as a test-cell baseline change. Cleanup must remove the copied fixture after the cell is stopped.

The required side effect for PASS is a deterministic chat marker generated by the Germ `clickDos` on the fixed page, observed through `query_chat_history` after `click_germ_component` or another explicitly recorded real client click path. The marker is `BBP_GERM_FIXED_CLICK_MARKER`. `germ_gui_part_dos execute=false` may still be used only as a semantic dry-run to prove the button's configured `clickDos`.

## Success Criteria

- `click_germ_component` remains the action under test; do not add a new action id and do not change `ActionCatalog`.
- `query_germ_screen` and `query_germ_hit_test` remain read-only.
- `germ_gui_part_dos` remains documented and treated as semantic `clickDos` execution only.
- `click_germ_component` result data records:
  - resolved target component id or class
  - selected screen coordinate
  - target bounds or bounds source
  - click path attempted
  - client method or screen event invocation evidence
  - warnings or failed candidate methods when present
- Runtime PASS requires the fixed local Germ test page `blackboxpro_fixed_click` from `docs/workflow/fixtures/germ/blackboxpro-fixed-click.yml`.
- Runtime PASS must include before/after evidence that the real click changed observable state. For the fixed page this is the chat marker `BBP_GERM_FIXED_CLICK_MARKER` appearing only after the real click.
- A successful `click_germ_component` response without a business side effect is not enough for PASS.
- If no real Germ page or business side-effect observer is available, report `BLOCKED`; do not substitute `germ_gui_part_dos`.
- Multi-bot orchestration remains out of scope.
