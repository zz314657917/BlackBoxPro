## 2. 已知问题修复（优先级 P0）

### 2.1 `query_screen_state` 返回暂停菜单 ✅ 已修复（⚠️ 编译未验证）

**现象**：测试执行时 `query_screen_state` 返回 `screenClass=GuiIngameMenu`，而非游戏主画面。

**根因**：`close_container` 只关容器，不关暂停菜单（`GuiIngameMenu` 不是容器）。

**修复**：新增 `close_screen` action（forge/fabric/neoforge 三端），调用 `displayGuiScreen(null)` / `setScreen(null)`。`executeCatalogCase` 在 resetBaseline 后改为调用 `close_screen`。

**待办**：下次执行时先编译并部署，验证 `query_screen_state` 稳定返回 `open=false`。

### 2.2 `query_block_state` 坐标偏移 ✅ 已修复已验证

**现象**：`block(0, -1, 0)` 查出 air，而非地板方块。

**修复**：`defaultParams` 改为 `block(0, 0, 0)`，玩家 y=166.5 时查 y=166（地板）。

**验证结果**：返回 `minecraft:stone_slab`（地板实际材质）✓

### 2.3 `batch` 超时（Gson 兼容性 + Error 未捕获）✅ 已修复已验证

**现象**：空 batch 也 timeout 10s。

**根因**：`JsonArray.isEmpty`（Gson 2.8.1+）在 MC 1.12.2 内置 Gson 2.2.4 上抛出 `NoSuchMethodError`（`Error` 子类），被 `catch Exception` 漏掉。

**修复**：
- `BatchAction.kt`：`isEmpty` → `size() == 0`
- `CommandDispatcher.kt`：`catch Exception` → `catch Throwable`
- `BlackBoxProForge.kt`：绑定 `RuntimeCommandDispatcher` 使子 action 解析正常

**验证结果**：batch 0.09s 返回 success，通过率 37→38 ✓

### 4.2 FX-BASE 实现方案（优先级 P0）

FX-BASE 是所有测试的基础前置，目标是确保每个用例开始前处于"干净的已知状态"：

**当前 `resetBaseline()` 已做**：
- teleport 到基准点
- gameMode 设为 survival
- clearInventory（服务端命令）

**需要补充**：
- `player.closeInventory()` → 关闭任何打开的容器
- 关闭客户端屏幕（解决 `query_screen_state` 问题）：发送 `close_container` action
- 确保玩家不处于骑乘状态
- 确保玩家不处于潜行/疾跑状态

**实现方式**：在 `BlackBoxFixtureManager.resetBaseline()` 的 `mainThread {}` 包裹中增加：
```kotlin
player.closeInventory()
// 发送 close_container 到客户端（清除任何打开的 GUI）
BlackBoxApi.sendAsync(player, "close_container", JsonObject())
    .thenRun { /* ignore */ }
```

### 4.3 `batch` 修复方案

**问题**：`BatchAction` 的 `executeBatchStep` 通过 `RuntimeCommandDispatcher.resolveAction()` 查找子 action，但 1.12.2 使用独立的 `ActionRegistry`，`RuntimeCommandDispatcher` 未绑定。

**修复方向**：在 1.12.2 的 `BlackBoxProForge.kt` 初始化时，调用 `RuntimeCommandDispatcher.bind()` 并传入 ActionRegistry 作为 resolver：
```kotlin
RuntimeCommandDispatcher.bind(
    loggerSupplier = ForgeBindings,
    mainThreadExecutor = object : RuntimeCommandDispatcher.MainThreadExecutor {
        override fun execute(task: () -> Unit) {
            Minecraft.getMinecraft().addScheduledTask(task)
        }
    },
    actionResolver = object : RuntimeCommandDispatcher.ActionResolver {
        override fun find(actionId: String) = ActionRegistry.find(actionId)
    }
)
```

### 4.4 `keep_alive` 修复方案

**问题**：测试发送硬编码 `id=1L`，与服务端实际 keepAlive id 不同导致踢出玩家。

**修复方向**：`keep_alive` 的测试应跳过，或改为"记录并回应最近一次服务端发来的 keepAlive id"。建议继续保留在 `pendingFixtureActions`，在专项测试中单独验证，而非放入全量回归。

## 8. 标准测试执行流程（SOP）

### 8.1 前置条件

- Git 状态：main 分支最新，无未提交改动
- 构建：`./gradlew buildAll --no-daemon`（根目录）
- 部署完成（见下方）

### 8.2 1.12.2 测试流程

```
1. 构建
   ./gradlew forge1122_build plugin_build --no-daemon

2. 部署
   # Plugin → Server
   Copy-Item 'plugin\build\libs\BlackBoxPro-Plugin-*.jar' 'F:\minecraft\server\paper-1.12.2\plugins\' -Force
   # Mod → Client（只保留正式 jar，删除 -dev.jar）
   Copy-Item 'mod\1.12.2\forge\build\libs\BlackBoxPro-forge-1.12.2-*.jar' \
     'F:\minecraft\client\dev-client\.minecraft\versions\1.12.2-Forge_14.23.5.2859\mods\' -Force
   Remove-Item '...\mods\BlackBoxPro-forge-1.12.2-*-dev.jar' -Force -EA SilentlyContinue

3. 启动服务端
   Stop-Process -Id <旧PID> -Force
   Start-Process -FilePath 'C:\Program Files\Java\jdk-1.8\bin\java.exe' \
     -ArgumentList '-Xms2G','-Xmx4G','-XX:+UseG1GC','-jar','Paper-1.12.2-build1620.jar','nogui' \
     -WorkingDirectory 'F:\minecraft\server\paper-1.12.2' -WindowStyle Hidden
   # 等待 logs\latest.log 出现 "Done"

4. 启动客户端
   Start-Process -FilePath 'cmd.exe' -ArgumentList '/c','F:\minecraft\client\dev-client\start.bat' -WindowStyle Normal
   # 等待服务端日志出现 "BlackBoxTester joined the game"
   # 如未自动加入，发送：
   # POST http://localhost:38081/execute {"action":"connect_to_server","params":{"ip":"127.0.0.1","port":25565}}

5. 运行测试
   POST http://localhost:38080/execute
   {"id":"run-1","action":"run_test","params":{"player":"BlackBoxTester","scope":"full"}}
   # 阻塞直到完成（约 50s），返回完整结果 JSON

6. 分析结果
   .data.passed / .data.failed / .data.skipped
   .data.results[] 查看每个 action 的状态和回执
```

> ⚠️ **注意**：
> - 服务端 JAR 文件名：`Paper-1.12.2-build1620.jar`（不是 `paper.jar`）
> - 停服：`Stop-Process -Id <PID> -Force`（不使用 RCON）
> - 客户端目录：`F:\minecraft\client\dev-client\.minecraft\versions\1.12.2-Forge_14.23.5.2859`
> - 每次部署后必须重启服务端；mod 变更还需重启客户端
