## 1. 版本概述

### 1.1 背景

BlackBoxPro 当前已覆盖 ~89 个客户端行为（移动、交互、GUI、战斗、截图、寻路等），但在"服务端主动获取客户端信息"方面存在明显短板。现有 8 个 Query Action 仅覆盖了玩家基础状态、物品、容器、药水效果、附近实体和聊天历史，大量高价值的客户端状态信息（方块、世界、记分板、Tab 列表、Boss Bar、屏幕类型等）无法从服务端获取。

这导致测试脚本在以下场景中无法完成自动化断言：
- 放置/破坏方块后验证方块类型是否正确
- 验证当前时间、天气、维度等世界状态
- 验证记分板侧边栏显示内容（大量服务端插件用记分板做 UI）
- 验证 Tab 列表中的玩家信息和权限组显示
- 判断当前打开的 GUI 类型（非容器界面如死亡屏幕、告示牌编辑等）
- 验证 Boss Bar 的显示状态

### 1.2 目标

v1.3.0 聚焦两个核心需求：

1. **服务端主动查询客户端信息**：新增 6 个 Query Action + 扩展 1 个现有 Query Action，覆盖方块、世界、Tab 列表、记分板、屏幕状态、Boss Bar 等客户端信息
2. **完善服务端 Plugin API**：为所有新增 Query Action 提供对应的 `XxxActions` 封装和 `HighLevelActions` 便捷方法，同步更新 `ActionParamRegistry` 命令补全

### 1.3 使用场景

```
场景 1：验证方块放置
  1. 发送 "place_block_at" → 在 (100, 64, 200) 放置方块
  2. 发送 "wait" → 等待 5 tick
  3. 发送 "query_block_state" → 查询 (100, 64, 200) 的方块类型
  4. 断言 data.blockId == "minecraft:stone" → 测试通过

场景 2：验证记分板 UI
  1. 发送 "chat_command" → 执行 /shop open
  2. 发送 "wait" → 等待 20 tick
  3. 发送 "query_scoreboard" → 读取侧边栏内容
  4. 断言 data.sidebar.entries 包含 "金币: 1000" → 测试通过

场景 3：验证 GUI 类型
  1. 发送 "chat_command" → 执行 /menu
  2. 发送 "wait" → 等待 10 tick
  3. 发送 "query_screen_state" → 获取当前屏幕类型
  4. 断言 data.screenType 包含 "ContainerScreen" → 测试通过

场景 4：验证世界状态
  1. 发送 "chat_command" → 执行 /time set day
  2. 发送 "query_world_state" → 查询世界时间
  3. 断言 data.timeOfDay == 1000 → 测试通过
```

### 2.2 覆盖缺口分析

| 缺口 | 可用 Minecraft API | 测试价值 | 优先级 |
|------|-------------------|----------|--------|
| 方块状态 | `world.getBlockState(pos)` / `world.getLightLevel()` / `world.getBiome()` | 方块验证是自动化测试最基础的需求 | P0 |
| 世界状态 | `world.timeOfDay` / `world.isRaining` / `world.registryKey` / `world.difficulty` | 时间/天气/维度是大量测试的前置条件 | P0 |
| Tab 列表 | `networkHandler.playerList` | 验证玩家上下线、权限组显示 | P1 |
| 记分板 | `world.scoreboard` | 大量插件用记分板做 UI | P1 |
| 屏幕状态 | `client.currentScreen` | 判断非容器 GUI 类型 | P1 |
| 玩家详细状态 | `player.armor` / `player.absorptionAmount` / `player.air` / `player.vehicle` 等 | 补充现有 query_player_state 的缺失字段 | P2 |
| Boss Bar | `client.inGameHud.bossBarHud` | Boss Bar 验证 | P2 |

| 编号 | 需求 | 优先级 |
|------|------|--------|
| F-1 | 新增 `query_block_state` 查询指定坐标方块类型、属性、光照、生物群系 | P0 |

| F-5 | 新增 `query_screen_state` 查询当前屏幕类型和状态 | P1 |
| F-6 | 扩展 `query_player_state` 补充盔甲值、吸收心、氧气、骑乘、游泳等字段 | P2 |
| F-7 | 新增 `query_boss_bar` 查询当前显示的 Boss 血条列表 | P2 |
| F-8 | 为所有新增 Query 提供 Plugin 端 `XxxActions` 封装 API | P0 |
| F-9 | `HighLevelActions` 新增对应便捷方法 | P1 |

### 2.4 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NF-1 | 所有 Query Action 在客户端主线程同步执行 | 读取 Minecraft 状态必须在主线程 |
| NF-2 | 单次查询耗时 < 50ms | 纯内存读取，无 IO 操作 |
| NF-3 | 查询失败不影响后续指令执行 | 异常捕获并回报 failure |
| NF-4 | Fabric / NeoForge 行为一致 | 两端返回数据结构完全相同 |
| NF-5 | 响应 payload 不超过 maxPayloadSize | 大数据量查询需支持 limit 参数 |

### 2.5 约束

- 所有新增 Query Action 均为客户端本地查询（纯读取客户端内存），不发送任何 C2S 网络包
- 返回数据结构使用 `JsonObject`，与现有 Query Action 风格一致
- Boss Bar 内部数据需通过 Mixin 或反射访问（`BossBarHud.bossBars` 为 private）

## 3. 架构设计

### 3.1 整体流程

所有新增 Query Action 遵循统一的"服务端主动查询"模式：

```
Server (Plugin)                          Client (Mod)
  │                                        │
  │  BlackBoxApi.sendAsync(player,         │
  │    "query_xxx", params)                │
  │ ──────────────────────────────────────▶│
  │                                        │  1. CommandDispatcher 调度到主线程
  │                                        │  2. QueryXxxAction.execute(params)
  │                                        │  3. 读取客户端内存状态（不发包）
  │                                        │  4. 序列化为 JsonObject
  │                                        │  5. 返回 ActionResult.ok(data)
  │  { status: "success",                  │
  │    data: { ... } }                     │
  │ ◀──────────────────────────────────────│
  │                                        │
  │  CompletableFuture<ResponseMessage>    │
  │  .thenAccept { resp ->                 │
  │      val data = resp.data              │
  │      // 断言验证                        │
  │  }                                     │
```

## 4. 需求一：query_block_state — 方块状态查询

### 4.1 功能说明

查询指定坐标的方块类型、BlockState 属性（朝向、半砖类型等）、光照等级和生物群系。纯客户端本地查询，无需 OP 权限。

### 4.2 玩家操作流程 → 代码设计

```
玩家行为：按 F3 看向方块，查看方块 ID 和属性
  ↓ 转化为
代码流程：
  1. 从 params 解析目标坐标 (x, y, z)
  2. world.getBlockState(BlockPos(x, y, z)) → 获取 BlockState
  3. Registries.BLOCK.getId(state.block) → 方块 ID（如 "minecraft:oak_stairs"）
  4. state.entries → 遍历所有 BlockState 属性（如 facing=north, half=bottom）
  5. world.getLightLevel(pos) → 总光照等级
  6. world.getLightLevel(LightType.BLOCK, pos) → 方块光照
  7. world.getLightLevel(LightType.SKY, pos) → 天空光照
  8. world.getBiome(pos) → 生物群系 ID
  9. 组装 JsonObject 返回
```

### 4.3 参数规格

```json
{
    "x": 100, "y": 64, "z": 200
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `x` | Int | 是 | 方块 X 坐标 |
| `y` | Int | 是 | 方块 Y 坐标 |
| `z` | Int | 是 | 方块 Z 坐标 |

### 4.4 Fabric 实现

```kotlin
package com.blackboxpro.fabric.action.query

import com.blackboxpro.fabric.action.ActionExecutor
import com.blackboxpro.fabric.action.ActionResult
import com.blackboxpro.fabric.util.requireInt
import com.google.gson.JsonObject
import net.minecraft.client.MinecraftClient
import net.minecraft.registry.Registries
import net.minecraft.util.math.BlockPos
import net.minecraft.world.LightType

/**
 * 查询指定坐标的方块状态。
 * Action ID: "query_block_state"
 */
class QueryBlockStateAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val client = MinecraftClient.getInstance()
        val world = client.world
            ?: return ActionResult.fail("World not available")

        val x = params.requireInt("x")
        val y = params.requireInt("y")
        val z = params.requireInt("z")
        val pos = BlockPos(x, y, z)

        val state = world.getBlockState(pos)

        val data = JsonObject().apply {
            // 方块 ID
            addProperty("blockId", Registries.BLOCK.getId(state.block).toString())

            // 是否为空气
            addProperty("isAir", state.isAir)

            // BlockState 属性（如 facing=north, half=bottom, waterlogged=false）
            val properties = JsonObject()
            state.entries.forEach { (property, value) ->
                properties.addProperty(property.name, value.toString())
            }
            add("properties", properties)

            // 光照等级
            addProperty("lightLevel", world.getLightLevel(pos))
            addProperty("blockLight", world.getLightLevel(LightType.BLOCK, pos))
            addProperty("skyLight", world.getLightLevel(LightType.SKY, pos))

            // 生物群系
            val biome = world.getBiome(pos)
            addProperty("biome", biome.key.map { it.value.toString() }.orElse("unknown"))

            // 硬度与抗性
            addProperty("hardness", state.getHardness(world, pos))

            // 坐标回显
            addProperty("x", x)
            addProperty("y", y)
            addProperty("z", z)
        }

        return ActionResult.ok("Block state queried at ($x, $y, $z)", data)
    }
}
```

### 4.5 NeoForge 差异

| Fabric (Yarn) | NeoForge (Mojang) |
|--------------|-------------------|

| `Registries.BLOCK.getId(block)` | `BuiltInRegistries.BLOCK.getKey(block)` |
| `world.getLightLevel(pos)` | `level.getMaxLocalRawBrightness(pos)` |
| `world.getLightLevel(LightType.BLOCK, pos)` | `level.getBrightness(LightType.BLOCK, pos)` |
| `world.getLightLevel(LightType.SKY, pos)` | `level.getBrightness(LightType.SKY, pos)` |
| `world.getBiome(pos)` | `level.getBiome(pos)` |
| `state.getHardness(world, pos)` | `state.getDestroySpeed(level, pos)` |
| `net.minecraft.util.math.BlockPos` | `net.minecraft.core.BlockPos` |

## 5. 需求二：query_world_state — 世界状态查询

### 5.1 功能说明

查询客户端当前世界的时间、天气、维度、难度等全局状态。无参数，直接读取 `ClientWorld` 属性。

### 5.2 玩家操作流程 → 代码设计

```
玩家行为：按 F3 查看调试屏幕中的世界信息
  ↓ 转化为
代码流程：
  1. client.world → 获取 ClientWorld 实例
  2. world.timeOfDay → 当前 tick 时间（0-24000 循环）
  3. world.time → 世界总 tick 数
  4. world.isRaining / world.isThundering → 天气状态
  5. world.registryKey.value → 维度 ID
  6. world.difficulty → 难度
  7. world.spawnPos → 世界出生点
  8. world.seaLevel → 海平面高度
  9. 组装 JsonObject 返回
```

### 5.3 参数规格

无参数。

### 5.4 Fabric 实现

```kotlin
package com.blackboxpro.fabric.action.query

import com.blackboxpro.fabric.action.ActionExecutor
import com.blackboxpro.fabric.action.ActionResult
import com.google.gson.JsonObject
import net.minecraft.client.MinecraftClient

/**
 * 查询世界全局状态。
 * Action ID: "query_world_state"
 */
class QueryWorldStateAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val client = MinecraftClient.getInstance()
        val world = client.world
            ?: return ActionResult.fail("World not available")

        val data = JsonObject().apply {
            // 时间
            addProperty("timeOfDay", world.timeOfDay)
            addProperty("worldTime", world.time)

            // 天气
            addProperty("raining", world.isRaining)
            addProperty("thundering", world.isThundering)

            // 维度
            addProperty("dimension", world.registryKey.value.toString())
            addProperty("hasSkyLight", world.dimension.hasSkyLight())
            addProperty("hasCeiling", world.dimension.hasCeiling())

            // 难度
            addProperty("difficulty", world.difficulty.getName())

            // 出生点
            val spawn = world.spawnPos
            addProperty("spawnX", spawn.x)
            addProperty("spawnY", spawn.y)
            addProperty("spawnZ", spawn.z)

            // 海平面
            addProperty("seaLevel", world.seaLevel)
        }

        return ActionResult.ok("World state queried", data)
    }
}
```

## 6. 需求三：query_tab_list — Tab 列表查询

### 7.1 功能说明

```
  4. 遍历条目：entry.owner → 行文本，entry.value → 分数

  6. 组装 JsonObject 返回
```

### 7.4 Fabric 实现

```kotlin
package com.blackboxpro.fabric.action.query

import com.blackboxpro.fabric.action.ActionExecutor
import com.blackboxpro.fabric.action.ActionResult
import com.blackboxpro.fabric.util.getStringOrNull
import com.google.gson.JsonArray
import com.google.gson.JsonObject
import net.minecraft.client.MinecraftClient
import net.minecraft.scoreboard.ScoreboardDisplaySlot

/**
 * 查询记分板显示内容。
 * Action ID: "query_scoreboard"
 */
class QueryScoreboardAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val client = MinecraftClient.getInstance()
        val world = client.world
            ?: return ActionResult.fail("World not available")

        val scoreboard = world.scoreboard
        val slot = params.getStringOrNull("slot") ?: "sidebar"

        val data = JsonObject()

        if (slot == "all" || slot == "sidebar") {
            data.add("sidebar", querySlot(scoreboard, ScoreboardDisplaySlot.SIDEBAR))
        }
        if (slot == "all" || slot == "list") {
            data.add("list", querySlot(scoreboard, ScoreboardDisplaySlot.LIST))
        }
        if (slot == "all" || slot == "below_name") {
            data.add("belowName", querySlot(scoreboard, ScoreboardDisplaySlot.BELOW_NAME))
        }

        return ActionResult.ok("Scoreboard queried", data)
    }

    private fun querySlot(scoreboard: net.minecraft.scoreboard.Scoreboard, slot: ScoreboardDisplaySlot): JsonObject {
        val result = JsonObject()
        val objective = scoreboard.getObjectiveForSlot(slot)

        if (objective == null) {
            result.addProperty("active", false)
            return result
        }

        result.addProperty("active", true)
        result.addProperty("objectiveName", objective.name)
        result.addProperty("displayName", objective.displayName.string)
        result.addProperty("renderType", objective.renderType.name.lowercase())

        val entries = JsonArray()
        scoreboard.getScoreboardEntries(objective).forEach { entry ->
            entries.add(JsonObject().apply {
                addProperty("name", entry.owner)
                addProperty("value", entry.value)
                // 自定义显示名（1.20.3+ 支持）
                entry.display?.let { addProperty("display", it.string) }
            })
        }
        result.add("entries", entries)

        return result
    }
}
```

## 8. 需求五：query_screen_state — 屏幕状态查询

### 8.1 功能说明

### 8.2 玩家操作流程 → 代码设计

```

  ↓ 转化为
代码流程：
  1. client.currentScreen → 获取当前 Screen 实例（可能为 null）
  2. screen == null → 无 GUI 打开
  3. screen.javaClass.simpleName → 屏幕类名（如 "InventoryScreen", "DeathScreen"）
  4. screen is HandledScreen<*> → 是否为容器界面
  5. screen.title → 屏幕标题
  6. 组装 JsonObject 返回
```

### 8.3 参数规格

### 8.4 Fabric 实现

```kotlin
package com.blackboxpro.fabric.action.query

import com.blackboxpro.fabric.action.ActionExecutor
import com.blackboxpro.fabric.action.ActionResult
import com.google.gson.JsonObject
import net.minecraft.client.MinecraftClient
import net.minecraft.client.gui.screen.ingame.HandledScreen
import net.minecraft.client.gui.screen.DeathScreen
import net.minecraft.client.gui.screen.DisconnectedScreen

/**
 * 查询当前屏幕状态。
 * Action ID: "query_screen_state"
 */
class QueryScreenStateAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val client = MinecraftClient.getInstance()
        val screen = client.currentScreen

        val data = JsonObject().apply {
            addProperty("open", screen != null)

            if (screen != null) {
                addProperty("screenClass", screen.javaClass.simpleName)
                addProperty("screenType", categorize(screen))
                addProperty("title", screen.title.string)
                addProperty("isContainer", screen is HandledScreen<*>)
                addProperty("isPauseScreen", screen.shouldPause())

                // 容器界面额外信息
                if (screen is HandledScreen<*>) {
                    val handler = client.player?.currentScreenHandler
                    if (handler != null) {
                        addProperty("windowId", handler.syncId)
                        addProperty("slotCount", handler.slots.size)
                    }
                }
            }
        }

        return ActionResult.ok("Screen state queried", data)
    }

    private fun categorize(screen: net.minecraft.client.gui.screen.Screen): String = when (screen) {
        is HandledScreen<*> -> "container"
        is DeathScreen -> "death"
        is DisconnectedScreen -> "disconnected"
        else -> "other"
    }
}
```

### 10.1 功能说明

## 12. 配置扩展

v1.3.0 的所有新增 Query Action 均为纯内存读取，无需新增客户端配置项。
