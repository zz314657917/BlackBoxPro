## 1. 项目总体架构

### 1.1 架构分层

```
┌──────────────────────────────────────────────────────────────────┐
│                        BlackBoxProFabric Mod                        │
├──────────────────────────────────────────────────────────────────┤
│  ┌─────────────┐                                                 │
│  │  Mod 入口    │  BlackBoxProFabric.kt (ClientModInitializer)      │
│  │  初始化所有层 │  注册 Channel、初始化 Dispatcher、加载配置       │
│  └──────┬──────┘                                                 │
│         │                                                        │
│  ┌──────▼──────┐     ┌──────────────┐     ┌──────────────┐      │
│  │  Network    │────▶│  Dispatcher  │────▶│   Actions    │      │
│  │  通讯层      │     │  调度层       │     │   行为层      │      │
│  │             │◀────│              │◀────│              │      │
│  └─────────────┘     └──────────────┘     └──────────────┘      │
│                                                                  │
│  ┌─────────────┐     ┌──────────────┐                            │
│  │  Config     │     │    Util      │                            │
│  │  配置管理    │     │   工具类      │                            │
│  └─────────────┘     └──────────────┘                            │
└──────────────────────────────────────────────────────────────────┘
```

### 1.2 数据流

```
Server                          Client (BlackBoxProFabric)
  │                                │
  │  Plugin Message (JSON)         │
  │  blackbox:command              │
  │ ──────────────────────────────▶│
  │                                │  1. NetworkHandler 接收并反序列化
  │                                │  2. Dispatcher 解析 action 字段
  │                                │  3. 若 delay > 0，调度延迟执行
  │                                │  4. 查找对应 ActionExecutor
  │                                │  5. 在主线程执行 Action
  │                                │  6. 构建 Response
  │  blackbox:response             │
  │ ◀──────────────────────────────│  7. 通过 NetworkHandler 回报
  │                                │
```

### 1.3 核心设计原则

1. **单一职责**：每个 Action 对应一个独立的 `ActionExecutor` 实现类，只负责一种行为。
2. **注册制**：所有 ActionExecutor 通过 `ActionRegistry` 注册，Dispatcher 通过 action ID 查找执行器，新增行为只需新增一个类并注册。
3. **主线程安全**：所有涉及 `MinecraftClient` 状态的操作必须通过 `MinecraftClient.getInstance().execute {}` 调度到渲染线程。
4. **必回报**：每条指令无论成功或失败，都必须通过 `blackbox:response` 回报结果，服务端可据此判断测试是否通过。
5. **不崩溃**：单条指令的异常不得导致 Mod 崩溃或网络断开，必须 catch 并回报 failure。

## 2. 包结构与模块职责

### 2.0 多模块项目结构

项目采用 Gradle 多模块结构，同时支持 Fabric 和 NeoForge 两个 Mod 加载器：

```

├── settings.gradle.kts                # 多模块声明（fabric, neoforge）
├── gradle.properties                  # 共享属性（版本号、依赖版本）
│
├── fabric/                            # Fabric 子模块
│   ├── build.gradle.kts               # Fabric Loom + Kotlin
│   └── src/main/
│       ├── kotlin/com/blackboxpro/fabric/  # Fabric 源码（Yarn 映射）
│       └── resources/fabric.mod.json    # Fabric 元数据
│
└── neoforge/                          # NeoForge 子模块
    ├── build.gradle.kts               # NeoGradle + Kotlin
    └── src/main/
        ├── kotlin/com/blackboxpro/neoforge/  # NeoForge 源码（Mojang 映射）
        └── resources/META-INF/neoforge.mods.toml  # NeoForge 元数据
```

两个子模块的代码结构完全对称，仅在以下 5 个平台特定文件上有差异：

| 文件 | Fabric | NeoForge |
|------|--------|----------|
| Mod 入口 | `BlackBoxProFabric.kt` (ClientModInitializer) | `BlackBoxProNeoForge.kt` (@Mod) |
| 网络处理 | `NetworkHandler.kt` (Fabric API) | `NetworkHandler.kt` (RegisterPayloadHandlersEvent) |
| 命令载荷 | `CommandPayload.kt` (PacketCodec) | `CommandPayload.kt` (StreamCodec) |
| 响应载荷 | `ResponsePayload.kt` (PacketCodec) | `ResponsePayload.kt` (StreamCodec) |
| 配置加载 | `BlackBoxConfig.kt` (FabricLoader) | `BlackBoxConfig.kt` (FMLPaths) |

其余文件（dispatcher、action、util）逻辑完全一致，仅包名和 Minecraft 类映射不同。

## 3. 通讯层设计与实现

### 3.1 Channel 注册

Fabric Networking API (v1) 要求在客户端初始化时注册自定义 Channel。BlackBoxProFabric 使用两个 Channel：

| Channel | Identifier | 方向 | 用途 |
|---|---|---|---|
| 指令通道 | `blackbox:command` | S→C | 接收服务端下发的行为指令 |
| 响应通道 | `blackbox:response` | C→S | 向服务端回报执行结果 |

#### BlackBoxChannels.kt 设计

```kotlin
package com.blackboxpro.fabric.network

import net.minecraft.util.Identifier

object BlackBoxChannels {
    val COMMAND: Identifier = Identifier.of("blackbox", "command")
    val RESPONSE: Identifier = Identifier.of("blackbox", "response")
}
```

### 3.2 CustomPayload 实现

Fabric 1.21.x 使用 `CustomPayload` 接口进行自定义数据传输。需要为两个 Channel 各实现一个 Payload 类。

#### CommandPayload.kt（接收指令）

```kotlin
package com.blackboxpro.fabric.network

import net.minecraft.network.PacketByteBuf
import net.minecraft.network.codec.PacketCodec
import net.minecraft.network.packet.CustomPayload

/**
 * 服务端 → 客户端的指令 Payload。
 * 数据格式：UTF-8 编码的 JSON 字符串。
 */
data class CommandPayload(val json: String) : CustomPayload {

    override fun getId(): CustomPayload.Id<CommandPayload> = ID

    companion object {
        val ID = CustomPayload.Id<CommandPayload>(BlackBoxChannels.COMMAND)

        val CODEC: PacketCodec<PacketByteBuf, CommandPayload> =
            PacketCodec.of(
                { payload, buf -> buf.writeString(payload.json) },
                { buf -> CommandPayload(buf.readString()) }
            )
    }
}
```

#### ResponsePayload.kt（发送响应）

```kotlin
package com.blackboxpro.fabric.network

import net.minecraft.network.PacketByteBuf
import net.minecraft.network.codec.PacketCodec
import net.minecraft.network.packet.CustomPayload

/**
 * 客户端 → 服务端的响应 Payload。
 */
data class ResponsePayload(val json: String) : CustomPayload {

    override fun getId(): CustomPayload.Id<ResponsePayload> = ID

    companion object {
        val ID = CustomPayload.Id<ResponsePayload>(BlackBoxChannels.RESPONSE)

        val CODEC: PacketCodec<PacketByteBuf, ResponsePayload> =
            PacketCodec.of(
                { payload, buf -> buf.writeString(payload.json) },
                { buf -> ResponsePayload(buf.readString()) }
            )
    }
}
```

### 3.3 NetworkHandler 设计

`NetworkHandler` 是通讯层的统一入口，负责：
1. 在 Mod 初始化时注册 Channel 和 Payload 编解码器
2. 注册 `blackbox:command` 的接收回调，将 JSON 反序列化为 `CommandMessage` 后交给 `CommandDispatcher`
3. 提供 `sendResponse()` 方法供 Dispatcher 回报结果

#### NetworkHandler.kt 设计

```kotlin
package com.blackboxpro.fabric.network

import com.blackboxpro.fabric.dispatcher.CommandDispatcher
import com.blackboxpro.fabric.dispatcher.CommandMessage
import com.google.gson.Gson
import com.google.gson.JsonObject
import net.fabricmc.fabric.api.client.networking.v1.ClientPlayNetworking
import net.fabricmc.fabric.api.networking.v1.PayloadTypeRegistry
import net.minecraft.client.MinecraftClient
import org.slf4j.LoggerFactory

object NetworkHandler {

    private val logger = LoggerFactory.getLogger("BlackBoxPro-Network")
    private val gson = Gson()

    /**
     * 注册 Payload 类型和接收回调。
     * 在 ClientModInitializer.onInitializeClient() 中调用。
     */
    fun register() {
        // 注册 S2C Payload 类型（接收指令）
        PayloadTypeRegistry.playS2C().register(CommandPayload.ID, CommandPayload.CODEC)
        // 注册 C2S Payload 类型（发送响应）
        PayloadTypeRegistry.playC2S().register(ResponsePayload.ID, ResponsePayload.CODEC)

        // 注册接收回调
        ClientPlayNetworking.registerGlobalReceiver(CommandPayload.ID) { payload, context ->
            val json = payload.json
            logger.debug("Received command: {}", json)

            try {
                val obj = gson.fromJson(json, JsonObject::class.java)
                val message = CommandMessage(
                    id = obj.get("id").asString,
                    action = obj.get("action").asString,
                    params = obj.getAsJsonObject("params") ?: JsonObject(),
                    delay = obj.get("delay")?.asLong ?: 0L
                )
                // 交给 Dispatcher 处理（此时已在网络线程，Dispatcher 负责调度到主线程）
                CommandDispatcher.dispatch(message)
            } catch (e: Exception) {
                logger.error("Failed to parse command: {}", json, e)
            }
        }

        logger.info("BlackBoxPro network channels registered.")
    }

    /**
     * 发送响应到服务端。
     * 必须在客户端网络可用时调用。
     */
    fun sendResponse(json: String) {
        val client = MinecraftClient.getInstance()
        if (client.networkHandler != null) {
            ClientPlayNetworking.send(ResponsePayload(json))
            logger.debug("Sent response: {}", json)
        } else {
            logger.warn("Cannot send response, network handler is null.")
        }
    }
}
```

### 3.4 注册时序

```
onInitializeClient()
    │
    ├── NetworkHandler.register()
    │       ├── PayloadTypeRegistry.playS2C().register(CommandPayload)
    │       ├── PayloadTypeRegistry.playC2S().register(ResponsePayload)
    │       └── ClientPlayNetworking.registerGlobalReceiver(CommandPayload.ID, callback)
    │
    ├── ActionRegistry.registerAll()
    │       └── 注册所有 ActionExecutor 到 Map
    │
    └── BlackBoxConfig.load()
            └── 从 config/blackboxpro-fabric.json 加载配置
```

### 3.5 消息编解码流程

```
接收指令:
  Minecraft 网络层 → PacketByteBuf → CommandPayload.CODEC.decode()
  → CommandPayload(json: String) → Gson 解析 → CommandMessage 数据类

发送响应:
  ResponseMessage 数据类 → Gson 序列化 → ResponsePayload(json: String)
  → ResponsePayload.CODEC.encode() → PacketByteBuf → Minecraft 网络层
```

### 4.2 ActionRegistry 设计

`ActionRegistry` 是一个全局的 action ID → `ActionExecutor` 映射表。所有行为执行器在 Mod 初始化时注册。

```kotlin
package com.blackboxpro.fabric.dispatcher

import com.blackboxpro.fabric.action.ActionExecutor
import org.slf4j.LoggerFactory

object ActionRegistry {

    private val logger = LoggerFactory.getLogger("BlackBoxPro-Registry")
    private val executors = mutableMapOf<String, ActionExecutor>()

    /**
     * 注册一个行为执行器。
     * 如果 action ID 已存在，会覆盖并打印警告。
     */
    fun register(actionId: String, executor: ActionExecutor) {
        if (executors.containsKey(actionId)) {
            logger.warn("Overriding executor for action: {}", actionId)

    fun find(actionId: String): ActionExecutor? = executors[actionId]
```

### 4.3 CommandDispatcher 设计

`CommandDispatcher` 是调度层的核心，负责：
1. 接收 `CommandMessage`
2. 处理 `delay` 延迟（通过 Minecraft 客户端 tick 调度）
3. 查找 `ActionExecutor`
4. 在主线程执行 Action
5. 构建 `ResponseMessage` 并通过 `NetworkHandler` 回报

#### 延迟执行策略

- `delay == 0`：立即通过 `MinecraftClient.execute {}` 调度到主线程执行
- `delay > 0`：将指令放入延迟队列，在客户端 tick 事件中倒计时，到期后执行

#### CommandDispatcher.kt

```kotlin
package com.blackboxpro.fabric.dispatcher

import com.blackboxpro.fabric.network.NetworkHandler
import com.google.gson.Gson
import net.fabricmc.fabric.api.client.event.lifecycle.v1.ClientTickEvents
import net.minecraft.client.MinecraftClient
import org.slf4j.LoggerFactory
import java.util.concurrent.ConcurrentLinkedQueue

object CommandDispatcher {

    private val logger = LoggerFactory.getLogger("BlackBoxPro-Dispatcher")
    private val gson = Gson()

    /**
     * 延迟队列中的条目。
     * remainingTicks 每 tick 递减，到 0 时执行。
     * 1 tick ≈ 50ms，delay(ms) / 50 = ticks
     */
    private data class DelayedCommand(
        val message: CommandMessage,
        var remainingTicks: Int
    )

    private val delayedQueue = ConcurrentLinkedQueue<DelayedCommand>()

    /**
     * 注册 tick 事件监听器，用于处理延迟指令。
     * 在 onInitializeClient() 中调用。
     */
    fun init() {
        ClientTickEvents.END_CLIENT_TICK.register { _ ->
            val iterator = delayedQueue.iterator()
            while (iterator.hasNext()) {
                val entry = iterator.next()
                entry.remainingTicks--
                if (entry.remainingTicks <= 0) {
                    iterator.remove()
                    executeOnMainThread(entry.message)
                }
            }
        }
    }

    /**
     * 分发指令。由 NetworkHandler 在网络线程调用。
     */
    fun dispatch(message: CommandMessage) {
        logger.info("Dispatching action: {} (id={})", message.action, message.id)

        if (message.delay > 0) {
            val ticks = (message.delay / 50).toInt().coerceAtLeast(1)
            logger.debug("Delaying action {} for {} ticks", message.action, ticks)
            delayedQueue.add(DelayedCommand(message, ticks))
        } else {
            executeOnMainThread(message)
        }
    }

    /**
     * 在客户端主线程执行指令。
     */
    private fun executeOnMainThread(message: CommandMessage) {
        MinecraftClient.getInstance().execute {
            val executor = ActionRegistry.find(message.action)
            if (executor == null) {
                logger.warn("Unknown action: {}", message.action)
                sendResponse(message.id, "failure", "Unknown action: ${message.action}")
                return@execute
            }

            try {
                val result = executor.execute(message.params)
                sendResponse(
                    id = message.id,
                    status = if (result.success) "success" else "failure",
                    message = result.message,
                    data = result.data
                )
            } catch (e: Exception) {
                logger.error("Action {} threw exception", message.action, e)
                sendResponse(message.id, "failure", "Exception: ${e.message}")
            }
        }
    }

    /**
     * 构建 ResponseMessage 并发送。
     */
    private fun sendResponse(
        id: String,
        status: String,
        message: String? = null,
        data: com.google.gson.JsonObject? = null
    ) {
        val response = ResponseMessage(id, status, message, data)
        val json = gson.toJson(response)
        NetworkHandler.sendResponse(json)
    }
}
```

### 4.4 调度流程图

```
NetworkHandler.callback (网络线程)
    │
    ▼
CommandDispatcher.dispatch(message)
    │
    ├── delay > 0 ?
    │       │
    │       ├── YES → 加入 delayedQueue (remainingTicks = delay/50)
    │       │           │
    │       │           ▼ (每 tick END_CLIENT_TICK)
    │       │         remainingTicks-- → 到 0 → executeOnMainThread()
    │       │
    │       └── NO → executeOnMainThread()
    │
    ▼
executeOnMainThread() (主线程)
    │
    ├── ActionRegistry.find(action)
    │       │
    │       ├── null → sendResponse(failure, "Unknown action")
    │       │
    │       └── executor → executor.execute(params)
    │                           │
    │                           ├── 成功 → sendResponse(success)
    │                           │
    │                           └── 异常 → catch → sendResponse(failure)
    │
    ▼
NetworkHandler.sendResponse(json) → 服务端
```

## 5. 行为层设计与实现

### 5.1 ActionExecutor 接口

所有行为执行器的统一接口。每个 Action 类实现此接口，只负责一种行为。

```kotlin
package com.blackboxpro.fabric.action

import com.google.gson.JsonObject

/**
 * 行为执行器接口。
 * 所有 Action 实现类必须实现此接口。
 */
interface ActionExecutor {

    /**
     * 执行行为。
     * 此方法保证在客户端主线程调用。
     *
     * @param params 行为参数（JSON 对象）
     * @return 执行结果
     */
    fun execute(params: JsonObject): ActionResult
}

/**
 * 行为执行结果。
 *
 * @param success 是否成功
 * @param message 可选的描述信息
 * @param data    可选的附加数据（如查询结果）
 */
data class ActionResult(
    val success: Boolean,
    val message: String? = null,
    val data: JsonObject? = null
) {
    companion object {
        fun ok(message: String? = null, data: JsonObject? = null) =
            ActionResult(true, message, data)

        fun fail(message: String) =
            ActionResult(false, message)
    }
}
```

### 5.3 Action 实现模板

每个 Action 的实现遵循统一模式：

```kotlin
class XxxAction : ActionExecutor {
    override fun execute(params: JsonObject): ActionResult {
        // 1. 从 params 解析参数
        val someValue = params.requireString("someKey")

        // 2. 获取 MinecraftClient 实例和 NetworkHandler
        val client = MinecraftClient.getInstance()
        val networkHandler = client.networkHandler
            ?: return ActionResult.fail("Not connected to server")

        // 3. 构造并发送对应的 Serverbound Packet
        networkHandler.sendPacket(SomeC2SPacket(someValue))

        // 4. 返回结果
        return ActionResult.ok()
    }
}
```

### 5.4 发包方式说明

所有原子行为的核心操作是通过 `ClientPlayNetworkHandler.sendPacket()` 发送 Serverbound Packet。

Fabric Yarn Mapping 中，所有 C2S（Client to Server）Packet 类位于：
- `net.minecraft.network.packet.c2s.play.*`

例如：
- `PlayerMoveC2SPacket.PositionAndOnGround` → 设置位置
- `PlayerActionC2SPacket` → 挖掘/丢弃等
- `PlayerInteractEntityC2SPacket` → 实体交互
- `ClickSlotC2SPacket` → 容器点击
- `ChatMessageC2SPacket` → 聊天消息

每个 Action 只需要：
1. 解析 JSON 参数
2. 构造对应的 C2S Packet
3. 调用 `networkHandler.sendPacket(packet)`
4. 返回 `ActionResult`

### 9.3 Click Mode 详解

容器点击是 Minecraft 协议中最复杂的部分。`mode` 和 `button` 的组合决定了点击行为：

```
Mode 0 - 普通点击:
  button=0 → 左键点击槽位（拾取/放下物品）
  button=1 → 右键点击槽位（拾取/放下一半）

Mode 1 - Shift 点击:
  button=0 → Shift+左键（快速转移物品）
  button=1 → Shift+右键（同上）

Mode 2 - 数字键:
  button=0~8 → 数字键 1~9（将槽位物品与快捷栏交换）

Mode 3 - 中键:
  button=2 → 鼠标中键（创造模式复制物品）

Mode 4 - 丢弃:
  button=0 → Q 键（丢弃单个物品）
  button=1 → Ctrl+Q（丢弃整组物品）

Mode 5 - 拖拽:
  button=0 → 开始左键拖拽
  button=1 → 左键拖拽添加槽位
  button=2 → 结束左键拖拽
  button=4 → 开始右键拖拽
  button=5 → 右键拖拽添加槽位
  button=6 → 结束右键拖拽
  button=8 → 开始中键拖拽（创造模式）
  button=9 → 中键拖拽添加槽位
  button=10 → 结束中键拖拽

Mode 6 - 双击:
  button=0 → 双击收集同类物品
```

### 9.5 容器操作流程


### 11.3 实现说明

#### 1.21.x 聊天签名机制

Minecraft 1.19.1+ 引入了聊天签名系统。在 1.21.x 中：

- `ChatMessageC2SPacket` 需要消息签名（`MessageSignatureData`）
- `CommandExecutionC2SPacket` 需要命令参数签名

直接构造这些 Packet 需要处理复杂的签名逻辑。推荐的实现方式是通过 `ClientPlayNetworkHandler` 的高层 API：

```kotlin
// 发送聊天消息（自动处理签名）
client.networkHandler?.sendChatMessage("Hello World")

// 发送命令（自动处理签名）
client.networkHandler?.sendChatCommand("gamemode creative")
```

### 11.4 注意事项

1. **消息长度限制**：Minecraft 聊天消息最大 256 字符，命令最大 32767 字符。超长消息应在 Action 中校验并回报 failure。
2. **签名服务器**：如果服务端启用了 `enforce-secure-profile`，客户端必须有有效的 Mojang 账号签名。测试环境建议关闭此选项。
3. **命令前缀**：`chat_command` 的 `command` 参数不应包含 `/` 前缀，Action 实现中做了容错处理。

## 15. 复合行为（宏指令）

### 15.1 设计理念

### 15.4 跨 tick 执行框架

复合行为需要跨多个 tick 执行。设计一个轻量级的 tick 回调机制：

```kotlin
package com.blackboxpro.fabric.action.composite

import net.fabricmc.fabric.api.client.event.lifecycle.v1.ClientTickEvents
import java.util.concurrent.ConcurrentLinkedQueue

/**
 * 跨 tick 任务调度器。
 * 复合行为通过此调度器安排延迟步骤。
 */
object TickScheduler {

    private data class ScheduledTask(
        var remainingTicks: Int,
        val task: () -> Unit
    )

    private val tasks = ConcurrentLinkedQueue<ScheduledTask>()

    fun init() {
        ClientTickEvents.END_CLIENT_TICK.register { _ ->
            val iterator = tasks.iterator()
            while (iterator.hasNext()) {
                val entry = iterator.next()
                entry.remainingTicks--
                if (entry.remainingTicks <= 0) {
                    iterator.remove()
                    entry.task()
                }
            }
        }
    }

    /**
     * 在指定 tick 数后执行任务。
     */
    fun schedule(delayTicks: Int, task: () -> Unit) {
        if (delayTicks <= 0) {
            task()
        } else {
            tasks.add(ScheduledTask(delayTicks, task))
        }
    }
}
```

```kotlin
package com.blackboxpro.fabric.action.composite

import com.blackboxpro.fabric.action.ActionExecutor
import com.blackboxpro.fabric.action.ActionResult
import com.blackboxpro.fabric.util.requireDouble
import com.google.gson.JsonObject
import net.minecraft.client.MinecraftClient
import net.minecraft.network.packet.c2s.play.PlayerMoveC2SPacket
import kotlin.math.atan2
import kotlin.math.sqrt

class LookAtAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val targetX = params.requireDouble("x")
        val targetY = params.requireDouble("y")
        val targetZ = params.requireDouble("z")

        val client = MinecraftClient.getInstance()
        val player = client.player
            ?: return ActionResult.fail("Player not available")
        val networkHandler = client.networkHandler
            ?: return ActionResult.fail("Not connected to server")

        // 计算从玩家眼睛位置到目标的 yaw 和 pitch
        val eyeX = player.x
        val eyeY = player.eyeY
        val eyeZ = player.z

        val dx = targetX - eyeX
        val dy = targetY - eyeY
        val dz = targetZ - eyeZ
        val horizontalDist = sqrt(dx * dx + dz * dz)

        val yaw = (-atan2(dx, dz) * 180.0 / Math.PI).toFloat()
        val pitch = (-atan2(dy, horizontalDist) * 180.0 / Math.PI).toFloat()

        // 更新本地玩家朝向
        player.yaw = yaw
        player.pitch = pitch

        // 发送到服务端
        networkHandler.sendPacket(
            PlayerMoveC2SPacket.LookAndOnGround(yaw, pitch, player.isOnGround)
        )

        return ActionResult.ok("Looking at ($targetX, $targetY, $targetZ) yaw=$yaw pitch=$pitch")
    }
}
```

```kotlin
package com.blackboxpro.fabric.action.composite

import com.blackboxpro.fabric.action.ActionExecutor
import com.blackboxpro.fabric.action.ActionResult
import com.blackboxpro.fabric.dispatcher.ActionRegistry
import com.blackboxpro.fabric.util.requireInt
import com.google.gson.JsonObject
import net.minecraft.client.MinecraftClient

/**
 * 完整挖掘方块：look_at → dig_start → 等待 → dig_finish
 *
 * 注意：此行为是异步的，会跨多个 tick 执行。
 * 初始调用立即返回 success，表示挖掘已开始。
 * 挖掘完成后不会额外回报（由 dig_finish 的结果决定）。
 */
class BreakBlockAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val x = params.requireInt("x")
        val y = params.requireInt("y")
        val z = params.requireInt("z")

        val client = MinecraftClient.getInstance()
        val player = client.player
            ?: return ActionResult.fail("Player not available")

        // Step 1: 看向方块中心
        val lookAt = ActionRegistry.find("look_at")
            ?: return ActionResult.fail("look_at action not registered")
        val lookParams = JsonObject().apply {
            addProperty("x", x + 0.5)
            addProperty("y", y + 0.5)
            addProperty("z", z + 0.5)
        }
        lookAt.execute(lookParams)

        // Step 2: 开始挖掘
        val digStart = ActionRegistry.find("dig_start")
            ?: return ActionResult.fail("dig_start action not registered")
        val digParams = JsonObject().apply {
            addProperty("x", x)
            addProperty("y", y)
            addProperty("z", z)
            addProperty("face", "top")
            addProperty("sequence", 0)
        }
        digStart.execute(digParams)

        // Step 3: 延迟后完成挖掘
        // 挖掘时间取决于方块硬度和工具，这里使用固定延迟
        // 实际实现应根据方块类型计算挖掘时间
        val breakTicks = calculateBreakTicks(client, x, y, z)

        TickScheduler.schedule(breakTicks) {
            val digFinish = ActionRegistry.find("dig_finish") ?: return@schedule
            val finishParams = JsonObject().apply {
                addProperty("x", x)
                addProperty("y", y)
                addProperty("z", z)
                addProperty("face", "top")
                addProperty("sequence", 1)
            }
            digFinish.execute(finishParams)
        }

        return ActionResult.ok("Breaking block at ($x, $y, $z), estimated ${breakTicks} ticks")
    }

    /**
     * 计算挖掘方块所需的 tick 数。
     * 基于方块硬度和玩家手持工具计算。
     */
    private fun calculateBreakTicks(client: MinecraftClient, x: Int, y: Int, z: Int): Int {
        val world = client.world ?: return 20
        val player = client.player ?: return 20
        val pos = net.minecraft.util.math.BlockPos(x, y, z)
        val state = world.getBlockState(pos)

        // 获取方块硬度
        val hardness = state.getHardness(world, pos)
        if (hardness < 0) return Int.MAX_VALUE // 不可破坏（基岩等）
        if (hardness == 0f) return 1 // 瞬间破坏

        // 简化计算：使用 Minecraft 的破坏速度公式
        val speed = player.getBlockBreakingSpeed(state)
        val ticks = if (speed > 0) {
            (hardness * 30.0f / speed).toInt().coerceAtLeast(1)
        } else {
            100 // 默认值
        }

        return ticks
    }
}
```

#### BatchAction.kt

```kotlin
package com.blackboxpro.fabric.action.composite

import com.blackboxpro.fabric.action.ActionExecutor
import com.blackboxpro.fabric.action.ActionResult
import com.blackboxpro.fabric.dispatcher.ActionRegistry
import com.google.gson.JsonObject

/**
 * 批量顺序执行多个指令。
 * actions 数组中的每个元素包含 action 和 params 字段。
 *
 * 如果某个子指令包含 wait 行为，后续指令会在 wait 完成后继续执行。
 */
class BatchAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val actionsArray = params.getAsJsonArray("actions")
            ?: return ActionResult.fail("Missing required field: actions")

        if (actionsArray.isEmpty) {
            return ActionResult.ok("Empty batch, nothing to do")
        }

        executeBatchStep(actionsArray.map { it.asJsonObject }, 0)

        return ActionResult.ok("Batch started (${actionsArray.size()} actions)")
    }

    private fun executeBatchStep(actions: List<JsonObject>, index: Int) {
        if (index >= actions.size) return

        val item = actions[index]
        val action = item.get("action").asString
        val actionParams = item.getAsJsonObject("params") ?: JsonObject()

        // 如果是 wait 行为，延迟后执行下一步
        if (action == "wait") {
            val ticks = actionParams.get("ticks")?.asInt ?: 0
            TickScheduler.schedule(ticks) {
                executeBatchStep(actions, index + 1)
            }
            return
        }

        // 执行当前行为
        val executor = ActionRegistry.find(action)
        if (executor != null) {
            executor.execute(actionParams)
        }

        // 立即执行下一步
        executeBatchStep(actions, index + 1)
    }
}
```

```kotlin
 * 在 batch 中使用时，会延迟后续指令的执行。
 */
class WaitAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val ticks = params.getIntOrDefault("ticks", 0)
        return ActionResult.ok("Waiting $ticks ticks (${ticks * 50}ms)")
    }
}
```

### 15.6 寻路算法设计 (pathfind_to)

`pathfind_to` 是最复杂的复合行为，需要实现客户端寻路。

#### 简化方案：直线移动

最简实现是直线移动，每 tick 向目标移动一步：

```
每 tick:
  1. 计算当前位置到目标的方向向量
  2. 按 speed 缩放步长（默认 4.317 blocks/s = 0.2158 blocks/tick）
  3. 发送 player_move 包
  4. 检查是否到达目标（距离 < 0.5）
  5. 到达则停止，否则继续下一 tick
```

#### 进阶方案：A* 寻路

如果需要绕过障碍物，可以实现基于客户端世界数据的 A* 寻路：

```
1. 以玩家当前位置为起点，目标坐标为终点
2. 使用 ClientWorld 的方块数据判断可通行性
3. 生成路径点列表
4. 每 tick 沿路径点移动
```

建议 v1.0.0 先实现直线移动，后续版本再加入 A* 寻路。

### 15.7 复合行为执行流程总结

```
服务端发送:
  { "action": "break_block", "params": { "x": 100, "y": 64, "z": 200 } }

客户端执行:
  Tick 0:
    ├── look_at(100.5, 64.5, 200.5)  → 计算 yaw/pitch → 发送 LookAndOnGround
    ├── dig_start(100, 64, 200, top)  → 发送 PlayerActionC2SPacket(START)
    └── 计算 breakTicks = 15

  Tick 1~14:
    └── (等待中)

  Tick 15:
    └── dig_finish(100, 64, 200, top) → 发送 PlayerActionC2SPacket(STOP)

回报:
  { "id": "xxx", "status": "success", "message": "Breaking block at (100, 64, 200), estimated 15 ticks" }
```

```kotlin
import com.google.gson.GsonBuilder

    val maxDelayTicks: Int = 6000,

    val defaultBreakTicks: Int = 20
)

data class PathfindingConfig(
    val maxDistance: Double = 100.0,
    val stepSize: Double = 0.2158,
    val arrivalThreshold: Double = 0.5
)

data class SafetyConfig(
    val enabled: Boolean = true,
    val allowedActions: List<String> = emptyList(),
    val blockedActions: List<String> = emptyList(),
    val requireServerHandshake: Boolean = false
)

data class BlackBoxConfig(
    val logging: LoggingConfig = LoggingConfig(),
    val network: NetworkConfig = NetworkConfig(),
    val execution: ExecutionConfig = ExecutionConfig(),
    val pathfinding: PathfindingConfig = PathfindingConfig(),
    val safety: SafetyConfig = SafetyConfig()
) {
    companion object {
        private val logger = LoggerFactory.getLogger("BlackBoxPro-Config")
        private val gson: Gson = GsonBuilder().setPrettyPrinting().create()
        private val configPath: Path = FabricLoader.getInstance()
            .configDir.resolve("blackboxpro-fabric.json")

        var current: BlackBoxConfig = BlackBoxConfig()
            private set

        fun load() {
            if (Files.exists(configPath)) {
                try {
                    val json = Files.readString(configPath)
                    current = gson.fromJson(json, BlackBoxConfig::class.java)
                    logger.info("Config loaded from {}", configPath)
                } catch (e: Exception) {
                    logger.error("Failed to load config, using defaults", e)
                    current = BlackBoxConfig()
                    save()
                }
            } else {
                current = BlackBoxConfig()
                save()
                logger.info("Default config created at {}", configPath)
            }
        }

        fun save() {
            try {
                Files.createDirectories(configPath.parent)
                Files.writeString(configPath, gson.toJson(current))
            } catch (e: Exception) {
                logger.error("Failed to save config", e)
            }
        }
    }
}
```

## 17. 线程模型与安全

### 17.1 Minecraft 客户端线程模型

```
┌─────────────────────────────────────────────────────────┐
│                    Minecraft Client                      │
│                                                          │
│  ┌──────────────┐     ┌──────────────┐                   │
│  │  Render Thread│     │ Netty Thread  │                  │
│  │  (主线程)     │     │ (网络线程)    │                   │
│  │              │     │              │                   │
│  │  - 游戏逻辑   │     │  - 收发网络包  │                   │
│  │  - 渲染       │     │  - 编解码     │                   │
│  │  - Tick 事件  │     │              │                   │
│  │  - GUI 操作   │     │              │                   │
│  └──────────────┘     └──────────────┘                   │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 17.2 BlackBoxProFabric 线程使用规则

| 操作 | 线程 | 说明 |
|---|---|---|
| 接收 Plugin Message | Netty 线程 | Fabric Networking 回调在网络线程触发 |
| JSON 反序列化 | Netty 线程 | 在回调中完成，避免阻塞主线程 |
| Action 执行 | 主线程 | 通过 `MinecraftClient.execute {}` 调度 |
| 发送 Packet | 主线程 | `sendPacket()` 内部会处理线程安全 |
| 发送 Response | 主线程 | 在 Action 执行完成后立即发送 |
| 延迟队列处理 | 主线程 | 在 `END_CLIENT_TICK` 事件中处理 |
| 配置加载 | 主线程 | 在 `onInitializeClient()` 中执行 |

### 17.3 关键线程安全点

#### 1. 网络回调 → 主线程调度

```kotlin
// NetworkHandler 中的回调（Netty 线程）
ClientPlayNetworking.registerGlobalReceiver(CommandPayload.ID) { payload, context ->
    // ✅ 这里在 Netty 线程，可以做 JSON 解析
    val message = parseCommand(payload.json)

    // ✅ 通过 Dispatcher 调度到主线程
    CommandDispatcher.dispatch(message)
    // Dispatcher 内部使用 MinecraftClient.execute {} 确保主线程执行
}
```

#### 2. 延迟队列的线程安全

```kotlin
// delayedQueue 使用 ConcurrentLinkedQueue
// - 添加：可能在 Netty 线程（dispatch 调用时）
// - 消费：在主线程（END_CLIENT_TICK 事件中）
// ConcurrentLinkedQueue 保证了线程安全
private val delayedQueue = ConcurrentLinkedQueue<DelayedCommand>()
```

#### 3. 禁止在非主线程操作客户端状态

```kotlin
// ❌ 错误：在网络回调中直接操作客户端
ClientPlayNetworking.registerGlobalReceiver(...) { payload, context ->
    val player = MinecraftClient.getInstance().player
    player?.yaw = 90f  // 危险！非主线程修改玩家状态
}

// ✅ 正确：调度到主线程
ClientPlayNetworking.registerGlobalReceiver(...) { payload, context ->
    MinecraftClient.getInstance().execute {
        val player = MinecraftClient.getInstance().player
        player?.yaw = 90f  // 安全：在主线程执行
    }
}
```

### 17.4 Tick 时序

```
每个游戏 Tick (≈50ms):
  │
  ├── START_CLIENT_TICK
  │
  ├── 游戏逻辑更新
  │   ├── 玩家输入处理
  │   ├── 实体更新
  │   └── 世界更新
  │
  ├── END_CLIENT_TICK
  │   ├── CommandDispatcher: 处理延迟队列
  │   └── TickScheduler: 处理复合行为延迟步骤
  │
  └── 渲染帧
```

所有 BlackBoxProFabric 的 tick 回调注册在 `END_CLIENT_TICK`，确保在游戏逻辑更新完成后执行，此时客户端状态是最新的。

## 18. 错误处理规范

### 18.1 错误处理原则

1. **必回报**：每条指令无论成功或失败，都必须回报 Response
2. **不崩溃**：单条指令的异常不得导致 Mod 崩溃或网络断开
3. **有信息**：failure 响应必须包含有意义的错误描述
4. **可追溯**：所有错误记录到日志，包含指令 ID 和 action 类型

### 18.2 错误分类

| 错误类型 | 处理方式 | 示例 |
|---|---|---|
| 参数缺失 | 回报 failure + 缺失字段名 | `Missing required field: x` |
| 参数类型错误 | 回报 failure + 期望类型 | `Field 'x' expected Double` |
| 参数值非法 | 回报 failure + 合法范围 | `Slot must be 0-8, got 10` |
| 未知 Action | 回报 failure + action ID | `Unknown action: foo_bar` |
| 客户端状态异常 | 回报 failure + 状态描述 | `Not connected to server` |
| 实体未找到 | 回报 failure + entity ID | `Entity not found: 42` |
| 安全检查拒绝 | 回报 failure + 原因 | `Action blocked by safety config` |
| 运行时异常 | catch + 回报 failure + 异常信息 | `Exception: NullPointerException` |

### 18.3 Dispatcher 层错误处理

```kotlin
// CommandDispatcher.executeOnMainThread()
try {
    val result = executor.execute(message.params)
    sendResponse(
        id = message.id,
        status = if (result.success) "success" else "failure",
        message = result.message,
        data = result.data
    )
} catch (e: IllegalArgumentException) {
    // 参数错误（由 requireXxx 抛出）
    logger.warn("Invalid params for action {}: {}", message.action, e.message)
    sendResponse(message.id, "failure", "Invalid params: ${e.message}")
} catch (e: Exception) {
    // 未预期的运行时异常
    logger.error("Action {} threw unexpected exception", message.action, e)
    sendResponse(message.id, "failure", "Internal error: ${e.message}")
}
```

### 18.4 Action 层错误处理模板

```kotlin
class SomeAction : ActionExecutor {
    override fun execute(params: JsonObject): ActionResult {
        // 1. 参数解析（requireXxx 会抛 IllegalArgumentException，由 Dispatcher catch）
        val x = params.requireInt("x")

        // 2. 前置条件检查（返回 fail，不抛异常）
        val client = MinecraftClient.getInstance()
        val networkHandler = client.networkHandler
            ?: return ActionResult.fail("Not connected to server")
        val player = client.player
            ?: return ActionResult.fail("Player not available")
        val world = client.world
            ?: return ActionResult.fail("World not loaded")

        // 3. 业务逻辑校验
        if (x < -30000000 || x > 30000000) {
            return ActionResult.fail("Coordinate out of range: x=$x")
        }

        // 4. 执行操作
        networkHandler.sendPacket(...)

        // 5. 返回成功
        return ActionResult.ok("Done")
    }
}
```

### 18.5 安全检查流程

如果配置中启用了安全检查 (`safety.enabled = true`)，Dispatcher 在执行 Action 前需要检查：

```kotlin
fun isActionAllowed(actionId: String): Boolean {
    val config = BlackBoxConfig.current.safety
    if (!config.enabled) return true

    // 黑名单优先
    if (config.blockedActions.contains(actionId)) return false

    // 白名单为空表示允许全部
    if (config.allowedActions.isEmpty()) return true

    return config.allowedActions.contains(actionId)
}
```

### 19.8 Mod 入口最终形态

```kotlin
package com.blackboxpro.fabric

import com.blackboxpro.fabric.action.composite.TickScheduler
import com.blackboxpro.fabric.config.BlackBoxConfig
import com.blackboxpro.fabric.dispatcher.ActionRegistry
import com.blackboxpro.fabric.dispatcher.CommandDispatcher
import com.blackboxpro.fabric.network.NetworkHandler
import net.fabricmc.api.ClientModInitializer
import org.slf4j.LoggerFactory

object BlackBoxProFabric : ClientModInitializer {

    private val logger = LoggerFactory.getLogger("BlackBoxProFabric")

    override fun onInitializeClient() {
        // 1. 加载配置
        BlackBoxConfig.load()

        // 2. 注册所有行为执行器
        ActionRegistry.registerAll()

        // 3. 初始化调度器
        CommandDispatcher.init()

        // 4. 初始化 Tick 调度器（复合行为用）
        TickScheduler.init()

        // 5. 注册网络通道（最后注册，确保其他组件已就绪）
        NetworkHandler.register()

        logger.info("BlackBoxProFabric v${} loaded. {} actions registered.",
            /* version */ "1.0.0",
            ActionRegistry.size()
        )
    }
}
```
