## 1. 功能概述

### 1.1 背景

BlackBoxPro 作为 Minecraft 自动化黑盒测试框架，当前已覆盖移动、交互、GUI 操作、战斗等 ~85 个行为。但在测试过程中缺乏视觉证据采集能力——当测试断言失败时，开发者无法直观看到客户端当时的画面状态。

### 1.2 目标

为客户端 Mod（Fabric / NeoForge）新增截图功能，支持：

1. 服务端通过指令触发客户端截图
2. 截图文件按玩家和测试维度隔离存储，便于多玩家并行测试时追溯
3. 截图自动编号，同一测试会话内按序递增
4. 截图完成后将文件路径等元信息回报服务端

### 1.3 使用场景

```
服务端测试脚本:
  1. 发送 "chat_command" → 玩家执行 /warp shop
  2. 发送 "wait" → 等待 40 tick（2 秒）加载
  3. 发送 "screenshot" → 截取当前画面作为视觉证据
  4. 断言响应中 filePath 存在 → 测试通过
```

## 2. 需求分析

### 2.1 功能需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| F-1 | 服务端可通过 `screenshot` action 触发客户端截图 | P0 |
| F-2 | 截图文件按 `玩家名/测试ID` 目录隔离存储 | P0 |
| F-3 | 同一测试会话内截图自动递增编号（001, 002, ...） | P0 |
| F-4 | 截图完成后回报文件路径、文件大小、截图尺寸 | P0 |
| F-5 | 支持自定义截图文件名前缀（可选） | P1 |
| F-6 | 支持配置截图保存根目录 | P1 |
| F-7 | 服务端插件提供 `ScreenshotActions` 辅助 API | P1 |

### 2.2 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NF-1 | 截图操作不阻塞客户端主线程 | 像素读取在渲染线程完成，文件 IO 异步处理 |
| NF-2 | 单次截图耗时 < 500ms | 含文件写入 |
| NF-3 | 截图失败不影响后续指令执行 | 异常捕获并回报 failure |
| NF-4 | Fabric / NeoForge 行为一致 | 两端截图结果可互换验证 |

### 2.3 约束

- Minecraft 截图 API 必须在渲染线程（主线程）调用
- 截图文件格式固定为 PNG
- 文件命名需兼容 Windows / Linux / macOS 文件系统（无特殊字符）

## 4. 截图存储与命名规范

### 4.1 目录结构

```
<minecraft_run_dir>/screenshots/blackboxpro/
└── <playerName>/
    └── <testId>/
        ├── 001_<prefix>.png
        ├── 002_<prefix>.png
        └── 003.png              # 无 prefix 时仅编号
```

- `screenshots/blackboxpro/`：截图根目录，与 Minecraft 原生 `screenshots/` 同级但隔离
- `<playerName>/`：玩家名目录，区分不同测试客户端
- `<testId>/`：测试 ID 目录，区分同一玩家的不同测试会话

### 4.2 文件命名规则

```
格式: {序号}_{前缀}.png
序号: 三位数字，从 001 开始递增，同一 testId 目录下自动计算
前缀: 可选，由服务端 params.prefix 指定

示例:
  001_before_open.png    # 有前缀
  002_after_open.png     # 有前缀
  003.png                # 无前缀
```

### 4.3 编号计算逻辑

```kotlin
// 扫描目标目录下已有的 PNG 文件，提取最大编号 + 1
fun nextIndex(directory: Path): Int {
    if (!Files.exists(directory)) return 1
    val pattern = Regex("^(\\d{3}).*\\.png$")
    return Files.list(directory)
        .map { it.fileName.toString() }
        .mapNotNull { pattern.matchEntire(it)?.groupValues?.get(1)?.toIntOrNull() }
        .max()
        .orElse(0) + 1
}
```

编号上限 999，超出后回报 failure（实际测试场景不会触及此限制）。

### 4.4 玩家名安全处理

玩家名可能包含文件系统不允许的字符，需做清洗：

```kotlin
fun sanitizeFileName(name: String): String =
    name.replace(Regex("[^a-zA-Z0-9_\\-.]"), "_")
```

## 5. 客户端 Mod 实现

### 5.1 ScreenshotHelper 工具类

负责帧缓冲捕获和文件写入，与 `ScreenshotAction` 解耦。

```kotlin
package com.blackboxpro.fabric.util

import net.minecraft.client.MinecraftClient
import net.minecraft.client.gl.Framebuffer
import net.minecraft.client.texture.NativeImage
import org.slf4j.LoggerFactory
import java.nio.file.Files
import java.nio.file.Path

/**
 * 截图工具类。
 * 帧缓冲读取必须在渲染线程（主线程）调用。
 */
object ScreenshotHelper {

    private val logger = LoggerFactory.getLogger("BlackBoxPro-Screenshot")

    /**
     * 截图结果。
     */
    data class ScreenshotResult(
        val filePath: Path,
        val width: Int,
        val height: Int,
        val fileSize: Long
    )

    /**
     * 捕获当前帧缓冲并保存为 PNG。
     * 必须在主线程调用。
     *
     * @param directory 目标目录
     * @param fileName 文件名（不含扩展名）
     * @return 截图结果
     */
    fun capture(directory: Path, fileName: String): ScreenshotResult {
        val client = MinecraftClient.getInstance()
        val framebuffer: Framebuffer = client.framebuffer

        // 从帧缓冲读取像素数据
        val image = ScreenshotRecorder.takeScreenshot(framebuffer)

        // 确保目录存在
        Files.createDirectories(directory)

        val filePath = directory.resolve("$fileName.png")

        try {
            // 写入 PNG 文件
            image.writeTo(filePath)

            val fileSize = Files.size(filePath)
            logger.info("Screenshot saved: {} ({}x{}, {} bytes)", filePath, image.width, image.height, fileSize)

            return ScreenshotResult(
                filePath = filePath,
                width = image.width,
                height = image.height,
                fileSize = fileSize
            )
        } finally {
            image.close()
        }
    }

    /**
     * 计算目录下的下一个截图编号。
     */
    fun nextIndex(directory: Path): Int {
        if (!Files.exists(directory)) return 1
        val pattern = Regex("^(\\d{3}).*\\.png$")
        return Files.list(directory).use { stream ->
            stream.map { it.fileName.toString() }
                .mapNotNull { pattern.matchEntire(it)?.groupValues?.get(1)?.toIntOrNull() }
                .max { a, b -> a.compareTo(b) }
                .orElse(0) + 1
        }
    }

    /**
     * 清洗文件名，移除文件系统不允许的字符。
     */
    fun sanitize(name: String): String =
        name.replace(Regex("[^a-zA-Z0-9_\\-.]"), "_")
}
```

> **Fabric vs NeoForge 差异**：
> - Fabric：`net.minecraft.client.util.ScreenshotRecorder.takeScreenshot(Framebuffer)`
> - NeoForge：`net.minecraft.client.Screenshot.takeScreenshot(Framebuffer)` （Mojang 映射）
> - 其余逻辑完全一致

### 5.2 ScreenshotAction 行为执行器

```kotlin
package com.blackboxpro.fabric.action.client

import com.blackboxpro.fabric.action.ActionExecutor
import com.blackboxpro.fabric.action.ActionResult
import com.blackboxpro.fabric.config.BlackBoxConfig
import com.blackboxpro.fabric.util.ScreenshotHelper
import com.blackboxpro.fabric.util.getStringOrNull
import com.google.gson.JsonObject
import net.minecraft.client.MinecraftClient
import java.nio.file.Path

/**
 * 截图行为执行器。
 *
 * 在客户端主线程捕获当前帧缓冲，保存为 PNG 文件，
 * 并将文件路径、尺寸等元信息回报服务端。
 *
 * Action ID: "screenshot"
 */
class ScreenshotAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val client = MinecraftClient.getInstance()
        val player = client.player
            ?: return ActionResult.fail("Player not available")

        // ── 参数解析 ──
        // playerName: 用于目录隔离，默认取当前玩家名
        val playerName = params.getStringOrNull("playerName")
            ?: player.gameProfile.name
        // testId: 测试会话 ID，用于区分不同测试
        val testId = params.getStringOrNull("testId") ?: "default"
        // prefix: 可选的文件名前缀
        val prefix = params.getStringOrNull("prefix")

        // ── 构建目标路径 ──
        val screenshotRoot = client.runDirectory.toPath()
            .resolve("screenshots")
            .resolve("blackboxpro")
        val directory = screenshotRoot
            .resolve(ScreenshotHelper.sanitize(playerName))
            .resolve(ScreenshotHelper.sanitize(testId))

        // ── 计算编号 ──
        val index = ScreenshotHelper.nextIndex(directory)
        if (index > 999) {
            return ActionResult.fail("Screenshot index overflow (max 999) for testId=$testId")
        }
        val indexStr = index.toString().padStart(3, '0')

        // ── 构建文件名 ──
        val fileName = if (prefix != null) {
            "${indexStr}_${ScreenshotHelper.sanitize(prefix)}"
        } else {
            indexStr
        }

        // ── 执行截图 ──
        val result = ScreenshotHelper.capture(directory, fileName)

        // ── 构建响应数据 ──
        val data = JsonObject().apply {
            // 返回相对于 minecraft 运行目录的路径
            val relativePath = client.runDirectory.toPath().relativize(result.filePath)
            addProperty("filePath", relativePath.toString().replace('\\', '/'))
            addProperty("width", result.width)
            addProperty("height", result.height)
            addProperty("fileSize", result.fileSize)
            addProperty("index", index)
        }

        return ActionResult.ok("Screenshot saved: $fileName.png", data)
    }
}
```

## 6. 服务端插件实现

### 6.1 ScreenshotActions API

```kotlin
package com.blackboxpro.plugin.api.action

import com.blackboxpro.plugin.api.BlackBoxApi
import com.blackboxpro.plugin.channel.ResponseMessage
import com.google.gson.JsonObject
import org.bukkit.entity.Player
import java.util.concurrent.CompletableFuture

/**
 * 截图行为快捷 API。
 */
object ScreenshotActions {

    /**
     * 触发客户端截图。
     *
     * @param player 目标玩家
     * @param testId 测试会话 ID，用于目录隔离
     * @param prefix 可选的文件名前缀
     * @param playerName 可选的玩家名覆盖（默认使用客户端当前玩家名）
     */
    fun screenshot(
        player: Player,
        testId: String = "default",
        prefix: String? = null,
        playerName: String? = null
    ): CompletableFuture<ResponseMessage> =
        BlackBoxApi.sendAsync(player, "screenshot", JsonObject().apply {
            addProperty("testId", testId)
            if (prefix != null) addProperty("prefix", prefix)
            if (playerName != null) addProperty("playerName", playerName)
        })
}
```

## 9. 线程模型与安全

### 9.1 截图线程要求

```
CommandDispatcher (网络线程)
    │
    ▼ MinecraftClient.execute { }
ScreenshotAction.execute() (主线程/渲染线程)
    │
    ├── ScreenshotRecorder.takeScreenshot()  ← 必须主线程，读取 GL 帧缓冲
    ├── NativeImage.writeTo()                ← 文件 IO，在主线程完成（PNG 编码 + 写入）
    │
    ▼
ActionResult 返回 → Dispatcher 回报响应
```

关键约束：
- `ScreenshotRecorder.takeScreenshot()` 内部调用 OpenGL 读取帧缓冲，必须在渲染线程执行
- `NativeImage.writeTo()` 包含 PNG 编码和文件写入，耗时取决于分辨率
- 当前设计在主线程同步完成截图全流程，避免跨线程传递 `NativeImage` 的生命周期问题
- 若未来性能成为瓶颈，可将 PNG 编码 + 写入拆分到异步线程（需拷贝像素数据）

### 9.2 并发安全

- 编号计算基于文件系统扫描，单客户端内串行执行（主线程），无并发问题
- 多客户端（不同玩家）各自独立目录，互不干扰
- `ScreenshotHelper` 为无状态工具类，线程安全

## 10. 错误处理

| 场景 | 处理方式 | 响应 |
|------|----------|------|
| 玩家未连接 | 前置检查 | `failure: "Player not available"` |
| 编号溢出 (>999) | 前置检查 | `failure: "Screenshot index overflow"` |
| 目录创建失败 | 异常捕获 | `failure: "Failed to create directory: ..."` |
| 帧缓冲读取失败 | 异常捕获 | `failure: "Failed to capture framebuffer: ..."` |
| PNG 写入失败 | 异常捕获 | `failure: "Failed to write screenshot: ..."` |
| 参数中含非法字符 | sanitize 清洗 | 正常执行，字符被替换为 `_` |

所有异常均被 `CommandDispatcher` 的外层 try-catch 兜底，不会导致 Mod 崩溃。

### 验收标准

1. 服务端发送 `screenshot` 指令后，客户端在 `screenshots/blackboxpro/<playerName>/<testId>/` 下生成 PNG 文件
2. 响应 `data` 中包含正确的 `filePath`、`width`、`height`、`fileSize`、`index`
3. 同一 `testId` 下多次截图编号自动递增（001, 002, 003...）
4. 不同 `playerName` 的截图存储在各自独立目录中
5. 截图失败时回报 `failure` 且不影响后续指令执行
6. Fabric 和 NeoForge 两端行为一致
