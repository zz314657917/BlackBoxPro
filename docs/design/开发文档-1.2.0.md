# BlackBoxPro v1.2.0 开发文档 — 方块瞄准与 AI 寻路

## 1. 版本概述

v1.2.0 新增两项核心能力：

1. **方块瞄准（Look At Block）**：控制客户端玩家准星精确瞄准指定坐标的方块面，模拟真实玩家的"看向方块"行为
2. **AI 寻路移动（Navigate To）**：基于客户端 A* 寻路算法，控制玩家沿可行走路径移动到目标坐标，支持跳跃、避障

## 2. 需求分析

### 2.1 现有问题

**方块瞄准：**

当前 `look_at` action 仅接受一个 (x, y, z) 坐标点，将玩家视线指向该点。复合行为（`break_block`、`place_block_at`、`open_container`）统一使用 `look_at(x+0.5, y+0.5, z+0.5)` 瞄准方块中心。

这存在两个问题：
- 无法指定瞄准方块的哪个面（top/bottom/north/south/east/west），导致放置方块时方向不可控
- 瞄准方块中心不等于准星命中方块——当玩家距离方块较远或角度刁钻时，客户端的 `crosshairTarget` 可能并未命中目标方块

**寻路移动：**

当前 `pathfind_to` action 采用直线移动策略：每 tick 沿直线方向移动一个 stepSize，直接 `setPosition` + 发送移动包。

这存在严重缺陷：
- 无障碍物检测：直线路径上有方块会导致玩家卡墙
- 无跳跃能力：遇到 1 格高差无法自动跳跃
- 无重力模拟：Y 轴直线移动不符合物理规律
- 反作弊风险：直接 setPosition 跳跃式移动容易被服务端反作弊检测

### 2.2 目标能力

**`look_at_block`：**
- 输入方块坐标 + 目标面，计算该面中心点的精确坐标
- 设置玩家 yaw/pitch 使准星指向该面中心
- 发送 Look 包同步服务端
- 返回计算后的 yaw、pitch 和命中面信息

**`navigate_to`：**
- 输入目标坐标，客户端自动寻路
- A* 算法在客户端世界数据上搜索可行走路径
- 支持 1 格高差自动跳跃、避开障碍物
- 每 tick 模拟真实玩家移动（走路速度 4.317 m/s ≈ 0.2158 blocks/tick）
- 移动过程中自动调整朝向（面向行进方向）
- 到达目标或路径不可达时回报结果
- 支持超时取消

## 4. 详细设计

### 4.1 `look_at_block` — 方块面瞄准

#### 参数

```json
{
    "x": 100, "y": 64, "z": 200,
    "face": "top"
}
```

- `x`, `y`, `z`：方块坐标（整数）
- `face`：目标面，可选值 `top`/`bottom`/`north`/`south`/`east`/`west`，默认 `top`

#### 执行流程

```
1. 解析参数，获取方块坐标和目标面
2. BlockFaceUtil.calculateFaceCenter(x, y, z, face) 计算面中心的精确世界坐标
   - top:    (x+0.5, y+1.0, z+0.5)
   - bottom: (x+0.5, y+0.0, z+0.5)
   - north:  (x+0.5, y+0.5, z+0.0)
   - south:  (x+0.5, y+0.5, z+1.0)
   - west:   (x+0.0, y+0.5, z+0.5)
   - east:   (x+1.0, y+0.5, z+0.5)
3. calculateYawPitch(faceCenter - playerEyePos) 计算 yaw/pitch
4. 设置 player.yaw/pitch
5. 发送 LookAndOnGround 包
6. 返回 ActionResult.ok(data: { yaw, pitch, face, targetX/Y/Z })
```

#### BlockFaceUtil 工具类

```kotlin
object BlockFaceUtil {
    data class FaceCenter(val x: Double, val y: Double, val z: Double)

    fun calculateFaceCenter(blockX: Int, blockY: Int, blockZ: Int, face: String): FaceCenter {
        return when (face.lowercase()) {
            "top", "up"       -> FaceCenter(blockX + 0.5, blockY + 1.0, blockZ + 0.5)
            "bottom", "down"  -> FaceCenter(blockX + 0.5, blockY.toDouble(), blockZ + 0.5)
            "north"           -> FaceCenter(blockX + 0.5, blockY + 0.5, blockZ.toDouble())
            "south"           -> FaceCenter(blockX + 0.5, blockY + 0.5, blockZ + 1.0)
            "west"            -> FaceCenter(blockX.toDouble(), blockY + 0.5, blockZ + 0.5)
            "east"            -> FaceCenter(blockX + 1.0, blockY + 0.5, blockZ + 0.5)
            else              -> FaceCenter(blockX + 0.5, blockY + 0.5, blockZ + 0.5) // center fallback
        }
    }
}
```

#### 返回 data

```json
{
    "yaw": -45.0,
    "pitch": 30.0,
    "face": "top",
    "targetX": 100.5,
    "targetY": 65.0,
    "targetZ": 200.5
}
```

### 4.2 `navigate_to` — AI 寻路移动

#### 参数

```json
{
    "x": 100.0, "y": 64.0, "z": 200.0,
    "speed": 1.0,
    "timeout": 600,
    "allowJump": true
}
```

- `x`, `y`, `z`：目标坐标（Double）
- `speed`：移动速度倍率，默认 1.0（正常走路速度）
- `timeout`：超时 tick 数，默认 600（30 秒）
- `allowJump`：是否允许跳跃越过 1 格高差，默认 true

#### 执行流程

```
1. 解析参数
2. 前置检查：
   - player 是否存在
   - 目标距离是否超过 maxDistance（配置项）
   - 是否已在目标附近（arrivalThreshold 内）
3. 调用 Pathfinder.findPath(startPos, targetPos, world, config)
   - 返回 List<PathNode>（有序路径点列表）
   - 如果返回空列表 → ActionResult.fail("No path found")
4. 创建 NavigationController 实例，传入路径和配置
5. NavigationController.start() 开始路径跟随
   - 通过 TickScheduler 每 tick 回调
   - 每 tick 移动一步，自动跳跃、转向
6. 立即返回 ActionResult.ok("Navigating to (...), path length=N")
   - 注意：navigate_to 是异步行为，返回时移动尚未完成
   - 到达/失败/超时时不再发送额外响应（与现有 pathfind_to 行为一致）
```

#### 返回 data

```json
{
    "pathLength": 15,
    "estimatedTicks": 70,
    "startX": 95.0,
    "startY": 64.0,
    "startZ": 195.0
}
```

### 4.3 PathNode 与 A* 寻路算法

#### PathNode 数据类

```kotlin
data class PathNode(
    val x: Int,
    val y: Int,
    val z: Int,
    val parent: PathNode? = null,
    var g: Double = 0.0,      // 从起点到此节点的实际代价
    var h: Double = 0.0,      // 启发式估计（到终点的曼哈顿距离）
    var jumpRequired: Boolean = false  // 到达此节点是否需要跳跃
) {
    val f: Double get() = g + h

    override fun equals(other: Any?): Boolean =
        other is PathNode && x == other.x && y == other.y && z == other.z

    override fun hashCode(): Int = x * 31 * 31 + y * 31 + z
}
```

#### Pathfinder 核心算法

```kotlin
object Pathfinder {

    fun findPath(
        start: BlockPos,
        goal: BlockPos,
        world: ClientWorld,
        config: NavigationConfig
    ): List<PathNode>

}
```

**A* 算法流程：**

```
openSet = PriorityQueue(按 f 值排序)
closedSet = HashSet<PathNode>()
startNode = PathNode(start.x, start.y, start.z, g=0, h=heuristic(start, goal))
openSet.add(startNode)

while openSet 非空 且 迭代次数 < maxIterations:
    current = openSet.poll()  // 取 f 最小的节点

    if current 在 goal 的 arrivalThreshold 内:
        return reconstructPath(current)  // 回溯路径

    closedSet.add(current)

    for neighbor in getNeighbors(current, world, config):
        if neighbor in closedSet: continue

        tentativeG = current.g + moveCost(current, neighbor)

        if neighbor 不在 openSet 或 tentativeG < neighbor.g:
            neighbor.parent = current
            neighbor.g = tentativeG
            neighbor.h = heuristic(neighbor, goal)
            openSet.add(neighbor)

return emptyList()  // 无路径
```

**邻居节点生成规则 `getNeighbors()`：**

```
对当前节点的 4 个水平方向（北/南/东/西）：
  1. 同层行走：neighbor(x±1, y, z±1)
     - 条件：neighbor 位置脚下有实心方块（可站立）
     - 条件：neighbor 位置和头部位置（y+1）均为可通过方块（空气/非实心）

  2. 向上跳跃：neighbor(x±1, y+1, z±1)
     - 条件：config.allowJump == true
     - 条件：当前位置头顶（y+2）可通过（跳跃空间）
     - 条件：目标位置脚下有实心方块
     - 条件：目标位置和头部位置均可通过
     - 标记 jumpRequired = true
     - 代价 = 1.5（跳跃比走路贵）

  3. 向下掉落：neighbor(x±1, y-1, z±1)
     - 条件：目标位置脚下有实心方块
     - 条件：目标位置和头部位置均可通过
     - 条件：当前位置水平方向可通过（不被墙挡住）
     - 代价 = 1.2（下落比走路略贵）
```

**方块可通过性判断：**

```kotlin
fun isPassable(world: ClientWorld, pos: BlockPos): Boolean {
    val state = world.getBlockState(pos)
    return !state.isSolidBlock(world, pos)
    // 空气、花、草、火把等非实心方块均可通过
}

fun isSolid(world: ClientWorld, pos: BlockPos): Boolean {
    val state = world.getBlockState(pos)
    return state.isSolidBlock(world, pos)
    // 石头、泥土、木板等实心方块可站立
}
```

**启发式函数：**

```kotlin
fun heuristic(a: PathNode, b: BlockPos): Double {
    // 曼哈顿距离（适合网格寻路）
    return abs(a.x - b.x) + abs(a.y - b.y) + abs(a.z - b.z).toDouble()
}
```

### 4.4 NavigationController — 路径跟随控制器

```kotlin
class NavigationController(
    private val path: List<PathNode>,
    private val speed: Double,
    private val timeout: Int
) {
    private var currentIndex = 0
    private var ticksElapsed = 0
    private var active = false

    fun start() { ... }
    fun stop() { ... }
    private fun tick() { ... }
}
```

**每 tick 执行逻辑：**

```
fun tick():
    if !active 或 ticksElapsed >= timeout:
        stop(); return

    ticksElapsed++
    player = MinecraftClient.getInstance().player ?: stop(); return

    targetNode = path[currentIndex]
    targetPos = (targetNode.x + 0.5, targetNode.y.toDouble(), targetNode.z + 0.5)

    // 计算到当前路径点的水平距离
    dx = targetPos.x - player.x
    dz = targetPos.z - player.z
    horizontalDist = sqrt(dx² + dz²)

    // 到达当前路径点 → 前进到下一个
    if horizontalDist < 0.3:
        currentIndex++
        if currentIndex >= path.size:
            // 到达终点
            stop(); return
        targetNode = path[currentIndex]
        重新计算 dx, dz, horizontalDist

    // 跳跃处理
    if targetNode.jumpRequired 且 player.isOnGround 且 targetNode.y > player.y:
        player.jump()  // 触发跳跃

    // 计算移动方向
    stepSize = config.stepSize * speed
    ratio = (stepSize / horizontalDist).coerceAtMost(1.0)
    newX = player.x + dx * ratio
    newZ = player.z + dz * ratio

    // Y 轴处理：
    //   - 跳跃中：不干预 Y，让客户端物理引擎处理
    //   - 下落：不干预 Y
    //   - 平地：使用目标 Y
    newY = if (player.isOnGround) targetNode.y.toDouble() else player.y

    // 自动转向（面向行进方向）
    (yaw, pitch) = calculateYawPitch(dx, 0.0, dz)
    player.yaw = yaw

    // 设置位置并发包
    player.setPosition(newX, newY, newZ)
    sendPacket(PlayerMoveC2SPacket.Full(newX, newY, newZ, yaw, player.pitch, player.isOnGround))

    // 调度下一 tick
    TickScheduler.schedule(1) { tick() }
```
