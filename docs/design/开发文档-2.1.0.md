## 1. 功能概述

### 1.1 背景

BlackBoxPro 当前已覆盖 ~100 个行为（移动、方块交互、容器操作、查询等），但所有 GUI 交互均为"直接发包"模式——`click_slot` 直接构造 `ServerboundContainerClickPacket`，绕过了 Minecraft 客户端的 GUI 渲染层。这意味着框架无法测试以下真实玩家场景：

- 玩家在聊天栏中看到一条带有 `[点击传送]` 的 JSON 富文本，鼠标点击后触发 `run_command`
- 玩家将鼠标悬停在聊天文字上，查看 HoverEvent 显示的提示信息（如物品详情、实体信息）
- 玩家在 GUI 容器中将鼠标移到某个物品槽位上，查看物品的 Tooltip 信息（名称、Lore、附魔等）

这些场景的共同特征是：**依赖鼠标位置与 GUI 渲染层的交互**，而非直接的网络包操作。

### 1.2 目标

为客户端 Mod（Fabric / NeoForge / Forge 1.12.2）新增鼠标行为模拟能力，支持：

1. 模拟点击聊天栏中的 JSON 富文本，触发 ClickEvent（`run_command`、`open_url`、`suggest_command`、`copy_to_clipboard`）
2. 查询聊天栏中指定消息的 HoverEvent 信息（`show_text`、`show_item`、`show_entity`）
3. 查询 GUI 容器中指定槽位的物品 Tooltip，返回内容须与玩家手动悬停时客户端渲染的样式完全一致
4. 修复 ChatHistoryBuffer 丢失 Style 信息的问题，使聊天历史保留完整的 ClickEvent/HoverEvent 数据

### 1.3 使用场景

```
场景 A：测试聊天文本点击
  1. 服务端向玩家发送带有 ClickEvent 的 JSON 文本（如 [点击传送] → run_command:/warp spawn）
  2. 发送 "query_chat_style" → 查询最近一条消息中包含"点击传送"的文本样式
  3. 断言响应中 clickEvent.action == "run_command"
  4. 发送 "click_chat_text" → 模拟点击该文本，触发 run_command
  5. 发送 "query_player_state" → 验证玩家已传送到 spawn

场景 B：测试聊天悬停信息
  1. 服务端向玩家发送带有 HoverEvent(show_item) 的文本
  2. 发送 "query_chat_style" → 查询该消息的 hover 信息
  3. 断言响应中 hoverEvent.action == "show_item"
  4. 断言 hoverEvent.contents 包含预期的物品 ID 和名称

场景 C：测试 GUI 物品 Tooltip
  1. 发送 "chat_command" → /shop 打开商店 GUI
  2. 发送 "wait" → 等待 20 tick
  3. 发送 "query_slot_tooltip" → 查询第 13 号槽位的物品 Tooltip
  4. 断言 Tooltip 包含预期的物品名称、Lore 描述、价格信息
  5. 发送 "screenshot" → 截图留证
```

## 2. 需求分析

### 2.1 功能需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| F-1 | 查询聊天消息的 Style 信息（ClickEvent / HoverEvent），支持按消息索引或文本内容匹配 | P0 |
| F-2 | 模拟点击聊天栏 JSON 文本，触发 ClickEvent 对应行为（run_command / suggest_command / copy_to_clipboard） | P0 |
| F-3 | 查询 GUI 容器中指定槽位的物品 Tooltip，返回结果须与玩家手动悬停时客户端渲染的 Tooltip 样式完全一致（含颜色、格式码、稀有度着色、Lore 斜体等） | P0 |
| F-4 | 修复 ChatHistoryBuffer（Runtime / Fabric）丢失 Style 信息的问题，存储完整 Component JSON | P0 |
| F-5 | 查询聊天消息的 HoverEvent 详细内容（show_text 文本 / show_item 物品 / show_entity 实体） | P0 |
| F-6 | 支持按坐标查询聊天 HUD 中的 Style（模拟鼠标悬停在聊天区域的特定位置） | P1 |
| F-7 | 服务端插件提供 `MouseActions` 辅助 API | P1 |
| F-8 | `HighLevelActions` 新增聊天点击、Tooltip 查询的语义化封装 | P1 |
| F-9 | `open_url` 类型的 ClickEvent 拦截并回报 URL，不实际打开浏览器（测试环境安全） | P1 |

### 2.2 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NF-1 | 所有鼠标模拟操作在客户端主线程执行 | GUI 状态读取和 Screen 方法调用必须在渲染线程 |
| NF-2 | 查询操作不产生副作用 | query_chat_style / query_slot_tooltip 为纯读取，不修改任何状态 |
| NF-3 | 三端行为一致 | Fabric / NeoForge / Forge 1.12.2 返回相同的数据结构（1.12.2 为兼容子集） |
| NF-4 | ChatHistoryBuffer 修复向后兼容 | `raw` 字段改为存储 JSON 后，`query_chat_history` 的 `plain` 字段行为不变 |
| NF-5 | 单次查询响应时间 < 50ms | 纯内存读取，无 IO 操作 |

### 2.3 约束

- `ChatHud.getTextStyleAt()` / `ChatComponent.getClickedComponentStyleAt()` 必须在主线程调用
- `Screen.handleComponentClicked(Style)` 会触发真实的命令发送 / 剪贴板操作，需在测试环境中注意副作用
- `open_url` 类型的 ClickEvent 在无头测试环境中不应打开浏览器，需拦截处理
- Forge 1.12.2 的 `GuiNewChat.getChatComponent()` 返回 `ITextComponent` 而非 `Style`，需额外适配
- 物品 Tooltip 内容依赖客户端语言设置和资源包，测试时需确保一致的客户端环境

## 4. 玩家操作流程分析与代码设计

### 4.1 需求一：点击聊天栏 JSON 文本

#### 4.1.1 真实玩家操作流程

```
1. 玩家在聊天区域看到一条带颜色/下划线的可点击文字（如 "[点击传送]"）
```

#### 4.1.3 代码设计：绕过坐标，直接从历史消息匹配

真实玩家通过鼠标坐标定位文字，但自动化测试中坐标不可靠（依赖窗口大小、字体渲染、聊天滚动位置）。更可靠的方案是：

**从 ChatHistoryBuffer 中按索引/文本匹配定位目标消息 → 反序列化为 Component 树 → 遍历树查找包含目标文本的节点 → 提取该节点的 Style → 执行 ClickEvent。**

```
设计决策：
┌─────────────────────────────────────────────────────────────────┐
│  方案 A（坐标模拟）：传入 mouseX, mouseY → 调用 getStyleAt()   │
│  ✗ 缺点：依赖窗口尺寸、字体缩放、聊天滚动位置，不稳定          │
│                                                                 │
│  方案 B（文本匹配）：传入 index + match → 从历史消息匹配 ✓     │
│  ✓ 优点：与渲染状态无关，确定性高，适合自动化测试               │
│  ✓ 前提：ChatHistoryBuffer 必须存储完整 Component JSON          │
└─────────────────────────────────────────────────────────────────┘
选择方案 B 作为主要实现，方案 A 作为 P1 补充（query_chat_style_at）。
```

核心算法——Component 树遍历匹配：

```kotlin
/**
 * 遍历 Component 树，查找包含 match 文本的叶子节点，返回其 Style。
 *
 * Component 树结构示例：
 *   TextComponent("前缀文字")
 *     └── siblings:
 *         ├── TextComponent("点击传送") { style: { clickEvent: {run_command, "/warp"} } }
 *         └── TextComponent("后缀文字")
 *
 * 遍历策略：深度优先，检查每个节点的 literal content 是否包含 match 字符串。
 * 匹配时优先返回自身 Style，若自身无 ClickEvent/HoverEvent 则向上继承父级 Style。
 */
fun findStyleByMatch(component: Component, match: String): StyleMatch? {
    // 检查当前节点的直接文本内容（不含 siblings）
    val directText = component.directContent()  // 仅当前节点的文字，不递归
    if (directText.contains(match)) {
        return StyleMatch(
            matchedText = directText,
            style = component.style  // Style 在 Component 树中向下继承
        )
    }
    // 递归检查 siblings
    for (sibling in component.siblings) {
        val result = findStyleByMatch(sibling, match)
        if (result != null) return result
    }
    return null
}
```

ClickEvent 执行策略——不直接调用 `handleComponentClicked`（会打开浏览器等不可控行为），而是按类型分别处理：

```kotlin
fun executeClickEvent(clickEvent: ClickEvent): ClickResult {
    return when (clickEvent.action) {
        RUN_COMMAND -> {
            // 直接通过 connection 发送命令，与真实点击行为一致
            val value = clickEvent.value
            if (value.startsWith("/")) {
                connection.sendCommand(value.removePrefix("/"))
            } else {
                connection.sendChat(value)
            }
            ClickResult(action = "run_command", value = value, executed = true)
        }
        SUGGEST_COMMAND -> {
            // 不打开聊天屏幕，仅回报建议内容
            ClickResult(action = "suggest_command", value = clickEvent.value, executed = false)
        }
        OPEN_URL -> {
            // 安全拦截：不打开浏览器，仅回报 URL
            ClickResult(action = "open_url", value = clickEvent.value, executed = false)
        }
        COPY_TO_CLIPBOARD -> {
            // 复制到剪贴板
            minecraft.keyboardHandler.clipboard = clickEvent.value
            ClickResult(action = "copy_to_clipboard", value = clickEvent.value, executed = true)
        }
        CHANGE_PAGE -> {
            ClickResult(action = "change_page", value = clickEvent.value, executed = false)
        }
    }
}
```

### 4.2 需求二：查询聊天文本的 Hover 信息

#### 4.2.1 真实玩家操作流程

```
1. 玩家在聊天区域看到一段文字（可能有特殊颜色/格式提示有 hover 信息）
2. 玩家按 T 打开聊天屏幕
3. 玩家将鼠标悬停在目标文字上方
4. 约 0.5 秒后，Minecraft 在鼠标位置渲染 Tooltip：
   - show_text: 显示多行文本
   - show_item: 显示物品名称、Lore、附魔等（与 GUI 物品 Tooltip 格式一致）
   - show_entity: 显示实体类型、名称、UUID
5. 玩家阅读 Tooltip 内容
6. 鼠标移开后 Tooltip 消失
```

### 4.3 需求三：查询 GUI 物品 Tooltip（与玩家手动悬停渲染一致）

#### 4.3.1 真实玩家操作流程

```
1. 玩家打开一个容器 GUI（箱子、商店、背包等）
2. 玩家将鼠标移动到某个物品槽位上方

   - 属性修饰符行（深绿色 §2 或红色 §c）
   - 最后几行：耐久度、"不可破坏"等属性标签（灰色）
6. 玩家阅读 Tooltip 信息
7. 鼠标移开后 Tooltip 消失
```

#### 4.3.3 关键设计约束：与玩家手动悬停渲染一致

玩家在客户端看到的 Tooltip 是由 `getTooltipLines()` / `getTooltip()` 返回的 `List<Component>` 直接渲染的。要保证查询结果与玩家看到的完全一致，必须满足：

1. **调用相同的 API**：使用 `Screen.getTooltipFromItem()` 而非直接调用 `ItemStack.getTooltipLines()`，因为前者是渲染管线实际调用的入口，可能包含 Mod 兼容层的额外处理
2. **传入相同的上下文**：`TooltipContext` 必须使用当前 `Level`（影响条件 Tooltip），`TooltipFlag` 必须与玩家当前模式一致（创造模式=ADVANCED，生存模式=NORMAL）
3. **保留完整的 Style 信息**：每行 Component 的颜色、粗体、斜体等格式必须完整序列化，不能只返回纯文本
4. **序列化为 §格式码**：为了让服务端能直接比对玩家看到的文本样式，需要将 Component 的 Style 转换为 Minecraft 标准 §格式码字符串（与 F3+H 或聊天中看到的格式一致）

```
设计决策：
┌─────────────────────────────────────────────────────────────────────┐
│  核心原则：查询结果 = 渲染管线的输入数据                            │
│                                                                     │
│  渲染管线：getTooltipFromItem(mc, stack) → List<Component> → 渲染   │
│  查询管线：getTooltipFromItem(mc, stack) → List<Component> → 序列化 │
│                                                                     │
│  两条管线的输入完全相同，只是输出端不同（渲染 vs JSON 序列化）。     │
│  这保证了查询结果与玩家看到的 Tooltip 在内容和样式上完全一致。      │
└─────────────────────────────────────────────────────────────────────┘
```

#### 4.3.4 代码设计：复用渲染管线的 Tooltip 获取路径

```kotlin
/**
 * 设计决策：
 * - 输入：slot 索引（与 click_slot 使用相同的编号体系）
 * - 通过 Screen.getTooltipFromItem() 获取 Tooltip（与渲染管线相同入口）
 * - 将每行 Component 序列化为三种格式：
 *   1. tooltip: 纯文本（去除所有格式，用于内容断言）
 *   2. tooltipFormatted: §格式码文本（与玩家在客户端看到的样式一致）
 *   3. tooltipJson: 完整 Component JSON（用于精确还原富文本结构）
 */
class QuerySlotTooltipAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val slotIndex = params.requireInt("slot")

        val client = Minecraft.getInstance()
        val player = client.player
            ?: return ActionResult.fail("Player not available")

        // 获取当前打开的容器屏幕
        val screen = client.screen
        val containerMenu = when {
            screen is AbstractContainerScreen<*> -> screen.menu
            else -> player.containerMenu  // 即使没有打开 GUI，也可以查询玩家背包
        }

        // 校验槽位范围
        if (slotIndex < 0 || slotIndex >= containerMenu.slots.size) {
            return ActionResult.fail(
                "Slot index $slotIndex out of range [0, ${containerMenu.slots.size})"
            )
        }

        val slot = containerMenu.slots[slotIndex]
        val itemStack = slot.item

        if (itemStack.isEmpty) {
            return ActionResult.ok("Slot $slotIndex is empty", JsonObject().apply {
                addProperty("slot", slotIndex)
                addProperty("empty", true)
            })
        }

        // ── 关键：使用与渲染管线相同的 API 获取 Tooltip ──
        // Screen.getTooltipFromItem() 是渲染时实际调用的方法，
        // 它内部调用 ItemStack.getTooltipLines() 并可能经过 Mod 兼容层处理。
        // TooltipFlag 根据玩家当前游戏模式决定，与手动悬停行为一致。
        val tooltipFlag = if (player.isCreative) {
            TooltipFlag.Default.ADVANCED
        } else {
            TooltipFlag.Default.NORMAL
        }
        val tooltipLines: List<Component> = Screen.getTooltipFromItem(client, itemStack)

        val data = JsonObject().apply {
            addProperty("slot", slotIndex)
            addProperty("empty", false)
            addProperty("itemId", BuiltInRegistries.ITEM.getKey(itemStack.item)?.toString() ?: "unknown")
            addProperty("itemName", itemStack.hoverName.string)
            addProperty("count", itemStack.count)
            addProperty("damage", itemStack.damageValue)
            addProperty("maxDamage", itemStack.maxDamage)

            // ── 格式 1：纯文本（去除所有格式码，用于内容断言） ──
            add("tooltip", JsonArray().apply {
                tooltipLines.forEach { add(it.string) }
            })

            // ── 格式 2：§格式码文本（与玩家在客户端看到的样式完全一致） ──
            // 将 Component 的 Style 转换为 §格式码前缀，保留颜色、粗体、斜体等
            add("tooltipFormatted", JsonArray().apply {
                tooltipLines.forEach { line ->
                    add(componentToLegacyString(line))
                }
            })

            // ── 格式 3：完整 Component JSON（用于精确还原富文本结构） ──
            val registryAccess = client.connection?.registryAccess()
            if (registryAccess != null) {
                add("tooltipJson", JsonArray().apply {
                    tooltipLines.forEach { line ->
                        add(Component.Serializer.toJson(line, registryAccess))
                    }
                })
            }
        }

        return ActionResult.ok("Tooltip queried for slot $slotIndex", data)
    }

    /**
     * 将 Component 转换为带 §格式码的旧式字符串。
     * 遍历 Component 树的每个节点，根据 Style 生成对应的 §格式码前缀。
     * 输出与玩家在客户端 Tooltip 中看到的文本样式完全一致。
     *
     * 格式码映射：
     *   §0-§f = 颜色（黑、深蓝、深绿...白）
     *   §l = 粗体, §o = 斜体, §n = 下划线, §m = 删除线, §k = 混淆, §r = 重置
     */
    private fun componentToLegacyString(component: Component): String {
        val sb = StringBuilder()
        component.visit({ style, text ->
            // 颜色码
            val color = style.color
            if (color != null) {
                val legacyCode = colorToLegacyCode(color)
                if (legacyCode != null) {
                    sb.append("§").append(legacyCode)
                }
            }
            // 格式码（必须在颜色码之后）
            if (style.isBold) sb.append("§l")
            if (style.isItalic) sb.append("§o")
            if (style.isUnderlined) sb.append("§n")
            if (style.isStrikethrough) sb.append("§m")
            if (style.isObfuscated) sb.append("§k")
            sb.append(text)
            java.util.Optional.empty<Unit>()
        }, Style.EMPTY)
        return sb.toString()
    }

    /**
     * 将 TextColor 映射为 §格式码字符。
     * 仅处理标准 16 色，自定义 RGB 颜色返回最近似的标准色。
     */
    private fun colorToLegacyCode(color: TextColor): Char? {
        // 标准命名颜色 → §格式码
        return when (color.value) {
            0x000000 -> '0'  // BLACK
            0x0000AA -> '1'  // DARK_BLUE
            0x00AA00 -> '2'  // DARK_GREEN
            0x00AAAA -> '3'  // DARK_AQUA
            0xAA0000 -> '4'  // DARK_RED
            0xAA00AA -> '5'  // DARK_PURPLE
            0xFFAA00 -> '6'  // GOLD
            0xAAAAAA -> '7'  // GRAY
            0x555555 -> '8'  // DARK_GRAY
            0x5555FF -> '9'  // BLUE
            0x55FF55 -> 'a'  // GREEN
            0x55FFFF -> 'b'  // AQUA
            0xFF5555 -> 'c'  // RED
            0xFF55FF -> 'd'  // LIGHT_PURPLE
            0xFFFF55 -> 'e'  // YELLOW
            0xFFFFFF -> 'f'  // WHITE
            else -> findNearestLegacyCode(color.value)  // 自定义 RGB → 最近似标准色
        }
    }

    /**
     * 对非标准 RGB 颜色，查找最近似的标准 16 色格式码。
     */
    private fun findNearestLegacyCode(rgb: Int): Char {
        val r = (rgb shr 16) and 0xFF
        val g = (rgb shr 8) and 0xFF
        val b = rgb and 0xFF
        val legacyColors = mapOf(
            '0' to 0x000000, '1' to 0x0000AA, '2' to 0x00AA00, '3' to 0x00AAAA,
            '4' to 0xAA0000, '5' to 0xAA00AA, '6' to 0xFFAA00, '7' to 0xAAAAAA,
            '8' to 0x555555, '9' to 0x5555FF, 'a' to 0x55FF55, 'b' to 0x55FFFF,
            'c' to 0xFF5555, 'd' to 0xFF55FF, 'e' to 0xFFFF55, 'f' to 0xFFFFFF
        )
        return legacyColors.minBy { (_, v) ->
            val dr = r - ((v shr 16) and 0xFF)
            val dg = g - ((v shr 8) and 0xFF)
            val db = b - (v and 0xFF)
            dr * dr + dg * dg + db * db
        }.key
    }
}
```

> **为什么使用 `Screen.getTooltipFromItem()` 而非直接 `ItemStack.getTooltipLines()`？**
>
> `Screen.getTooltipFromItem(minecraft, itemStack)` 是 Minecraft 渲染管线中实际调用的方法。
> 在 NeoForge 环境下，它会触发 `RenderTooltipEvent.GatherComponents` 事件，允许其他 Mod
> 修改 Tooltip 内容（如 JEI 添加物品来源信息、REI 添加配方提示等）。直接调用
> `ItemStack.getTooltipLines()` 会跳过这些 Mod 兼容层，导致查询结果与玩家实际看到的不一致。
>
> Fabric 端同理：`Screen.getTooltipFromItem()` 内部会触发 `ItemTooltipCallback` 事件。

## 5. 客户端 Mod 实现

### 5.1 ChatStyleHelper 工具类

负责 Component JSON 的反序列化、树遍历、Style 提取和序列化。三端共用逻辑，API 映射不同。

#### Runtime (NeoForge/Mojang mapping)

```kotlin
package com.blackboxpro.neoforge.util

import com.google.gson.JsonArray
import com.google.gson.JsonObject
import net.minecraft.client.Minecraft
import net.minecraft.network.chat.ClickEvent
import net.minecraft.network.chat.Component
import net.minecraft.network.chat.HoverEvent
import net.minecraft.network.chat.Style
import org.slf4j.LoggerFactory

/**
 * 聊天 Component 样式提取工具。
 * 从 Component JSON 中按文本匹配定位节点，提取 ClickEvent / HoverEvent。
 */
object ChatStyleHelper {

    private val logger = LoggerFactory.getLogger("BlackBoxPro-ChatStyle")

    /**
     * 样式匹配结果。
     */
    data class StyleMatch(
        val matchedText: String,
        val style: Style,
        val clickEvent: ClickEvent?,
        val hoverEvent: HoverEvent?
    )

    /**
     * 从 Component JSON 字符串中查找包含 match 文本的节点，返回其 Style。
     *
     * @param componentJson ChatHistoryBuffer 中存储的完整 Component JSON
     * @param match 要匹配的文本片段
     * @return 匹配结果，未找到返回 null
     */
    fun findStyleByMatch(componentJson: String, match: String): StyleMatch? {
        val registryAccess = Minecraft.getInstance().connection?.registryAccess()
            ?: return null
        val component = try {
            Component.Serializer.fromJson(componentJson, registryAccess)
        } catch (e: Exception) {
            logger.warn("Failed to deserialize component JSON: {}", e.message)
            return null
        } ?: return null

        return findInComponent(component, match)
    }

    /**
     * 递归遍历 Component 树，查找包含 match 文本的节点。
     * 遍历策略：深度优先，先检查当前节点的直接文本内容，再递归 siblings。
     */
    private fun findInComponent(component: Component, match: String): StyleMatch? {
        // 检查当前节点的直接文本内容（不含 siblings）
        val directText = getDirectText(component)
        if (directText.contains(match)) {
            val style = component.style
            return StyleMatch(
                matchedText = directText,
                style = style,
                clickEvent = style.clickEvent,
                hoverEvent = style.hoverEvent
            )
        }
        // 递归检查 siblings
        for (sibling in component.siblings) {
            val result = findInComponent(sibling, match)
            if (result != null) return result
        }
        return null
    }

    /**
     * 获取 Component 节点的直接文本内容（不含 siblings）。
     * Component.getString() 会递归包含 siblings，这里只取当前节点自身的文字。
     */
    private fun getDirectText(component: Component): String {
        // MutableComponent 的 contents 是 ComponentContents
        // 对于 literal 文本，contents.toString() 或通过 visitor 提取
        val builder = StringBuilder()
        component.contents.visit { text ->
            builder.append(text)
            java.util.Optional.empty<Unit>()
        }
        return builder.toString()
    }

    /**
     * 将 ClickEvent 序列化为 JSON。
     */
    fun serializeClickEvent(clickEvent: ClickEvent): JsonObject = JsonObject().apply {
        addProperty("action", clickEvent.action.name.lowercase())
        addProperty("value", clickEvent.value)
    }

    /**
     * 将 HoverEvent 序列化为 JSON。
     * 根据 HoverEvent 类型（show_text / show_item / show_entity）分别处理。
     */
    fun serializeHoverEvent(hoverEvent: HoverEvent): JsonObject = JsonObject().apply {
        // show_text
        hoverEvent.getValue(HoverEvent.Action.SHOW_TEXT)?.let { text ->
            addProperty("action", "show_text")
            addProperty("contents", text.string)
            return@apply
        }
        // show_item
        hoverEvent.getValue(HoverEvent.Action.SHOW_ITEM)?.let { itemInfo ->
            addProperty("action", "show_item")
            add("contents", JsonObject().apply {
                addProperty("id", itemInfo.item.toString())
                addProperty("count", itemInfo.count)
            })
            return@apply
        }
        // show_entity
        hoverEvent.getValue(HoverEvent.Action.SHOW_ENTITY)?.let { entityInfo ->
            addProperty("action", "show_entity")
            add("contents", JsonObject().apply {
                addProperty("type", entityInfo.type.toString())
                addProperty("id", entityInfo.id.toString())
                addProperty("name", entityInfo.name?.string)
            })
            return@apply
        }
    }

    /**
     * 将完整 Style 序列化为 JSON（含 color、bold、italic 等格式信息）。
     */
    fun serializeStyle(style: Style): JsonObject = JsonObject().apply {
        style.color?.let { addProperty("color", it.serialize()) }
        if (style.isBold) addProperty("bold", true)
        if (style.isItalic) addProperty("italic", true)
        if (style.isUnderlined) addProperty("underlined", true)
        if (style.isStrikethrough) addProperty("strikethrough", true)
        if (style.isObfuscated) addProperty("obfuscated", true)
        style.clickEvent?.let { add("clickEvent", serializeClickEvent(it)) }
        style.hoverEvent?.let { add("hoverEvent", serializeHoverEvent(it)) }
        style.insertion?.let { addProperty("insertion", it) }
    }
}
```

```kotlin
/**
 * 模拟点击聊天栏中的 JSON 富文本，触发 ClickEvent。
 *
 * 通过 ChatHistoryBuffer 中的消息索引 + 文本匹配定位目标 Component 节点，
 * 提取 ClickEvent 并根据类型执行对应行为。
 *
 * Action ID: "click_chat_text"
 *
 * 参数:
 *   - match: String (必填) 要匹配的文本片段
 *   - index: Int (可选, 默认 0) 聊天历史消息索引，0 = 最新一条
 *   - execute: Boolean (可选, 默认 true) 是否执行 ClickEvent（false 则仅查询不执行）
 */
class ClickChatTextAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val match = params.requireString("match")
        val index = params.getIntOrDefault("index", 0)
        val shouldExecute = params.get("execute")?.asBoolean ?: true

        val client = Minecraft.getInstance()
        val player = client.player
            ?: return ActionResult.fail("Player not available")
        val connection = client.connection
            ?: return ActionResult.fail("Not connected to server")

        // ── 从 ChatHistoryBuffer 获取目标消息 ──
        val entries = ChatHistoryBuffer.getRecent(index + 1)
        if (index >= entries.size) {
            return ActionResult.fail("Chat history index $index out of range (size: ${entries.size})")
        }
        val entry = entries[index]

        // ── 在 Component 树中查找匹配文本 ──
        val styleMatch = ChatStyleHelper.findStyleByMatch(entry.raw, match)
            ?: return ActionResult.fail("Text '$match' not found in chat message at index $index")

        val clickEvent = styleMatch.clickEvent
            ?: return ActionResult.fail("Text '$match' found but has no ClickEvent")

        // ── 构建响应数据 ──
        val data = JsonObject().apply {
            addProperty("matchedText", styleMatch.matchedText)
            add("clickEvent", ChatStyleHelper.serializeClickEvent(clickEvent))
        }

        // ── 执行 ClickEvent ──
        if (shouldExecute) {
            when (clickEvent.action) {
                ClickEvent.Action.RUN_COMMAND -> {
                    val value = clickEvent.value
                    if (value.startsWith("/")) {
                        connection.sendCommand(value.removePrefix("/"))
                    } else {
                        connection.sendChat(value)
                    }
                    data.addProperty("executed", true)
                }
                ClickEvent.Action.SUGGEST_COMMAND -> {
                    // suggest_command 不自动执行，仅回报
                    data.addProperty("executed", false)
                    data.addProperty("note", "suggest_command: value reported but not auto-executed")
                }
                ClickEvent.Action.OPEN_URL -> {
                    // 安全拦截：测试环境不打开浏览器
                    data.addProperty("executed", false)
                    data.addProperty("note", "open_url intercepted for safety")
                }
                ClickEvent.Action.COPY_TO_CLIPBOARD -> {
                    client.keyboardHandler.clipboard = clickEvent.value
                    data.addProperty("executed", true)
                }
                ClickEvent.Action.CHANGE_PAGE -> {
                    data.addProperty("executed", false)
                    data.addProperty("note", "change_page only works in book screen")
                }
            }
        } else {
            data.addProperty("executed", false)
        }

        return ActionResult.ok("ClickEvent found: ${clickEvent.action.name.lowercase()}", data)
    }
}
```

### 5.5 QuerySlotTooltipAction 行为执行器

```kotlin
package com.blackboxpro.neoforge.action.query

import com.blackboxpro.common.runtime.action.ActionExecutor
import com.blackboxpro.common.runtime.action.ActionResult
import com.blackboxpro.neoforge.util.requireInt
import com.blackboxpro.neoforge.util.getBooleanOrDefault
import com.google.gson.JsonArray
import com.google.gson.JsonObject
import net.minecraft.client.Minecraft
import net.minecraft.client.gui.screens.Screen
import net.minecraft.client.gui.screens.inventory.AbstractContainerScreen
import net.minecraft.core.registries.BuiltInRegistries
import net.minecraft.network.chat.Component
import net.minecraft.network.chat.Style
import net.minecraft.network.chat.TextColor
import net.minecraft.world.inventory.AbstractContainerMenu
import net.minecraft.world.item.TooltipFlag

/**
 * 查询 GUI 容器中指定槽位的物品 Tooltip。
 *
 * 使用与渲染管线相同的 Screen.getTooltipFromItem() 获取 Tooltip，
 * 保证返回结果与玩家手动悬停时客户端渲染的 Tooltip 样式完全一致。
 *
 * 返回三种格式：
 *   - tooltip: 纯文本（去除格式码，用于内容断言）
 *   - tooltipFormatted: §格式码文本（与玩家看到的样式一致，含颜色/粗体/斜体等）
 *   - tooltipJson: 完整 Component JSON（用于精确还原富文本结构）
 *
 * Action ID: "query_slot_tooltip"
 *
 * 参数:
 *   - slot: Int (必填) 槽位索引
 *   - advanced: Boolean (可选, 默认 false) 是否使用高级 Tooltip（显示 NBT 等调试信息）
 */
class QuerySlotTooltipAction : ActionExecutor {

    override fun execute(params: JsonObject): ActionResult {
        val slotIndex = params.requireInt("slot")
        val advanced = params.getBooleanOrDefault("advanced", false)

        val client = Minecraft.getInstance()
        val player = client.player
            ?: return ActionResult.fail("Player not available")

        // ── 获取当前容器 ──
        val containerMenu: AbstractContainerMenu = player.containerMenu

        // ── 校验槽位范围 ──
        if (slotIndex < 0 || slotIndex >= containerMenu.slots.size) {
            return ActionResult.fail(
                "Slot index $slotIndex out of range [0, ${containerMenu.slots.size})"
            )
        }

        val slot = containerMenu.slots[slotIndex]
        val itemStack = slot.item

        // ── 空槽位 ──
        if (itemStack.isEmpty) {
            return ActionResult.ok("Slot $slotIndex is empty", JsonObject().apply {
                addProperty("slot", slotIndex)
                addProperty("empty", true)
            })
        }

        // ── 获取 Tooltip：使用与渲染管线相同的入口 ──
        // Screen.getTooltipFromItem() 是渲染时实际调用的方法，
        // 会触发 NeoForge 的 RenderTooltipEvent.GatherComponents 事件，
        // 允许其他 Mod（JEI、REI 等）修改 Tooltip 内容。
        // TooltipFlag 根据玩家游戏模式或 advanced 参数决定，与手动悬停行为一致。
        val tooltipLines: List<Component> = Screen.getTooltipFromItem(client, itemStack)

        // 如果请求 advanced 模式但玩家非创造模式，需要手动获取 ADVANCED tooltip
        val finalLines = if (advanced && !player.isCreative) {
            itemStack.getTooltipLines(
                net.minecraft.world.item.Item.TooltipContext.of(client.level),
                player,
                TooltipFlag.Default.ADVANCED
            )
        } else {
            tooltipLines
        }

        // ── 获取物品 ID ──
        val itemId = BuiltInRegistries.ITEM.getKey(itemStack.item)?.toString() ?: "unknown"

        // ── 构建响应 ──
        val data = JsonObject().apply {
            addProperty("slot", slotIndex)
            addProperty("empty", false)
            addProperty("itemId", itemId)
            addProperty("itemName", itemStack.hoverName.string)
            addProperty("count", itemStack.count)
            addProperty("damage", itemStack.damageValue)
            addProperty("maxDamage", itemStack.maxDamage)

            // 格式 1：纯文本（去除所有格式码，用于内容断言）
            add("tooltip", JsonArray().apply {
                finalLines.forEach { add(it.string) }
            })

            // 格式 2：§格式码文本（与玩家在客户端看到的 Tooltip 样式完全一致）
            add("tooltipFormatted", JsonArray().apply {
                finalLines.forEach { line ->
                    add(componentToLegacyString(line))
                }
            })

            // 格式 3：完整 Component JSON（用于精确还原富文本结构）
            val registryAccess = client.connection?.registryAccess()
            if (registryAccess != null) {
                add("tooltipJson", JsonArray().apply {
                    finalLines.forEach { line ->
                        add(Component.Serializer.toJson(line, registryAccess))
                    }
                })
            }
        }

        return ActionResult.ok("Tooltip queried for slot $slotIndex", data)
    }

    /**
     * 将 Component 转换为带 §格式码的旧式字符串。
     * 遍历 Component 树的每个节点，根据 Style 生成对应的 §格式码前缀。
     * 输出与玩家在客户端 Tooltip 中看到的文本样式完全一致。
     */
    private fun componentToLegacyString(component: Component): String {
        val sb = StringBuilder()
        component.visit({ style, text ->
            val color = style.color
            if (color != null) {
                val legacyCode = colorToLegacyCode(color)
                if (legacyCode != null) {
                    sb.append("§").append(legacyCode)
                }
            }
            if (style.isBold) sb.append("§l")
            if (style.isItalic) sb.append("§o")
            if (style.isUnderlined) sb.append("§n")
            if (style.isStrikethrough) sb.append("§m")
            if (style.isObfuscated) sb.append("§k")
            sb.append(text)
            java.util.Optional.empty<Unit>()
        }, Style.EMPTY)
        return sb.toString()
    }

    /**
     * 将 TextColor 映射为 §格式码字符。
     * 标准 16 色直接映射，自定义 RGB 颜色查找最近似的标准色。
     */
    private fun colorToLegacyCode(color: TextColor): Char? {
        return when (color.value) {
            0x000000 -> '0'  // BLACK
            0x0000AA -> '1'  // DARK_BLUE
            0x00AA00 -> '2'  // DARK_GREEN
            0x00AAAA -> '3'  // DARK_AQUA
            0xAA0000 -> '4'  // DARK_RED
            0xAA00AA -> '5'  // DARK_PURPLE
            0xFFAA00 -> '6'  // GOLD
            0xAAAAAA -> '7'  // GRAY
            0x555555 -> '8'  // DARK_GRAY
            0x5555FF -> '9'  // BLUE
            0x55FF55 -> 'a'  // GREEN
            0x55FFFF -> 'b'  // AQUA
            0xFF5555 -> 'c'  // RED
            0xFF55FF -> 'd'  // LIGHT_PURPLE
            0xFFFF55 -> 'e'  // YELLOW
            0xFFFFFF -> 'f'  // WHITE
            else -> findNearestLegacyCode(color.value)
        }
    }

    private fun findNearestLegacyCode(rgb: Int): Char {
        val r = (rgb shr 16) and 0xFF
        val g = (rgb shr 8) and 0xFF
        val b = rgb and 0xFF
        val legacyColors = mapOf(
            '0' to 0x000000, '1' to 0x0000AA, '2' to 0x00AA00, '3' to 0x00AAAA,
            '4' to 0xAA0000, '5' to 0xAA00AA, '6' to 0xFFAA00, '7' to 0xAAAAAA,
            '8' to 0x555555, '9' to 0x5555FF, 'a' to 0x55FF55, 'b' to 0x55FFFF,
            'c' to 0xFF5555, 'd' to 0xFF55FF, 'e' to 0xFFFF55, 'f' to 0xFFFFFF
        )
        return legacyColors.minBy { (_, v) ->
            val dr = r - ((v shr 16) and 0xFF)
            val dg = g - ((v shr 8) and 0xFF)
            val db = b - (v and 0xFF)
            dr * dr + dg * dg + db * db
        }.key
    }
}
```

```kotlin
    fun queryChatStyle(
        player: Player,
        match: String,

    ): CompletableFuture<ResponseMessage> =

            addProperty("match", match)
            addProperty("index", index)
        })

     * 查询 GUI 容器中指定槽位的物品 Tooltip。

        player: Player,
```

## 9. 线程模型与安全

### 9.1 执行线程要求

```
CommandDispatcher (HTTP 处理线程)
    │
    ▼ Minecraft.getInstance().execute { }
Action.execute() (客户端主线程)
    │
    ├── click_chat_text:
    │     ├── ChatHistoryBuffer.getRecent()     ← ConcurrentLinkedDeque，线程安全
    │     ├── ChatStyleHelper.findStyleByMatch() ← 纯计算，无 MC 状态依赖
    │     ├── Component.Serializer.fromJson()    ← 需要 registryAccess（主线程可用）
    │     └── connection.sendCommand()           ← 必须主线程
    │
    ├── query_chat_style:
    │     ├── ChatHistoryBuffer.getRecent()     ← 同上
    │     ├── ChatStyleHelper.findStyleByMatch() ← 同上
    │     └── 纯读取，无副作用
    │
    └── query_slot_tooltip:
          ├── player.containerMenu.slots[i]     ← 必须主线程（容器状态）
          ├── itemStack.getTooltipLines()        ← 必须主线程（访问 Level）
          └── 纯读取，无副作用
```

关键约束：

- `ChatHistoryBuffer` 使用 `ConcurrentLinkedDeque`，读取操作线程安全，但 `Component.Serializer.fromJson()` 需要 `registryAccess`，该对象绑定到网络连接，应在主线程访问
- `connection.sendCommand()` / `connection.sendChat()` 必须在主线程调用（Netty channel 的线程安全由 MC 内部保证，但 `click_chat_text` 的 `RUN_COMMAND` 分支涉及状态变更，应在主线程执行）
- `player.containerMenu` 的 slots 列表在主线程更新，查询时必须在主线程以避免读到不一致状态
- `itemStack.getTooltipLines()` 内部可能访问 `Level`（如条件 Tooltip），必须在主线程

### 9.2 ChatHistoryBuffer 修改的并发安全

```
聊天事件回调线程（可能是 Netty 线程）
    │
    ▼ ChatHistoryBuffer.addMessage()
    │   ├── Component.Serializer.toJson()  ← 需要 registryAccess
    │   ├── buffer.addFirst()              ← ConcurrentLinkedDeque，线程安全
    │   └── buffer.removeLast()            ← 同上
    │
    ▼ 注意：NeoForge 的 ClientChatReceivedEvent 在主线程触发
           Fabric 的 ClientReceiveMessageEvents 也在主线程触发
           Forge 1.12.2 的 ClientChatReceivedEvent 在主线程触发
           → 三端的 addMessage 均在主线程执行，registryAccess 可安全访问
```

### 9.3 ClickEvent 执行的副作用分析

| ClickEvent.Action | 副作用 | 安全性 |
|-------------------|--------|--------|
| `RUN_COMMAND` | 向服务端发送命令/聊天消息 | ✓ 安全，与 `chat_command` Action 等价 |
| `SUGGEST_COMMAND` | 无（仅回报值） | ✓ 安全，无副作用 |
| `OPEN_URL` | 被拦截，不打开浏览器 | ✓ 安全，仅回报 URL |
| `COPY_TO_CLIPBOARD` | 修改系统剪贴板 | ⚠ 低风险，测试环境可接受 |
| `CHANGE_PAGE` | 无（仅在 BookScreen 生效） | ✓ 安全，当前不处理 |

## 10. 错误处理

### 10.1 click_chat_text 错误场景

| 场景 | 处理方式 | 响应 |
|------|----------|------|
| 玩家未连接 | 前置检查 | `failure: "Player not available"` |
| 网络连接不可用 | 前置检查 | `failure: "Not connected to server"` |
| index 超出历史范围 | 范围检查 | `failure: "Chat history index N out of range (size: M)"` |
| match 文本未找到 | 遍历结果检查 | `failure: "Text 'xxx' not found in chat message at index N"` |
| 匹配到文本但无 ClickEvent | Style 检查 | `failure: "Text 'xxx' found but has no ClickEvent"` |
| Component JSON 反序列化失败 | 异常捕获 | `failure: "Failed to deserialize chat component"` |
| registryAccess 不可用 | 降级处理 | `failure: "Registry access not available"` |
| RUN_COMMAND 发送失败 | 异常捕获 | `failure: "Failed to execute command: ..."` |

### 10.2 query_chat_style 错误场景

| 场景 | 处理方式 | 响应 |

| match 文本未找到 | 遍历结果检查 | `failure: "Text 'xxx' not found in chat message at index N"` |
| Component JSON 反序列化失败 | 异常捕获 | `failure: "Failed to deserialize chat component"` |
| registryAccess 不可用 | 降级处理 | `failure: "Registry access not available"` |

### 10.3 query_slot_tooltip 错误场景

| 场景 | 处理方式 | 响应 |
|------|----------|------|
| 玩家未连接 | 前置检查 | `failure: "Player not available"` |
| slot 索引超出范围 | 范围检查 | `failure: "Slot index N out of range [0, M)"` |
| 空槽位 | 正常返回 | `success` + `{ empty: true }`（非错误） |
| getTooltipLines 异常 | 异常捕获 | `failure: "Failed to get tooltip: ..."` |
| Level 不可用（Tooltip 上下文） | 降级处理 | 使用 `EMPTY` 上下文，Tooltip 可能不完整但不报错 |

### 10.4 ChatHistoryBuffer 修复的错误处理

| 场景 | 处理方式 | 影响 |
|------|----------|------|
| Component.Serializer.toJson() 异常 | try-catch 降级为 `message.string` | `raw` 字段为纯文本，Style 查询将失败 |
| registryAccess 为 null | 降级为 `message.string` | 同上 |
| 序列化后 JSON 过大（极端情况） | 不做截断，依赖 buffer maxSize 控制总量 | 内存占用略增 |

所有异常均被 `CommandDispatcher` 的外层 try-catch 兜底，不会导致 Mod 崩溃。
